# 0.2.54 固件查询失败与完整入口复查

官方查询可能同时读到当前固件版本、又在查询兼容目录时失败。失败行中的 `latest_version: null` 不能表示已是最新版本，也不能提供升级目标。本轮将准确设备的失败观察与原有严格成功解析分开，原成功、提醒和恢复解析规则保持不变。

| 流程 | 修复与独立复查 |
| --- | --- |
| 检查返回失败 | 零及非零退出码的明确失败行均不产生升级预览、可用提醒或已最新结论；保留同一序列号、设备类型和 CLI 身份下已读到的当前版本与原始错误 |
| 官方流程结束后的回读 | 兼容目录失败时不显示旧目标为可用版本，不根据当前版本等于旧目标推断升级成功；CLI 身份变化拒绝新观察 |
| 版本与提示 | 当前版本、本次目标和未确认的可用版本分开；中英文兼容目录 HTTP404 显示具体原因；退出、释放或恢复尚未确认时保留优先核对提示和占用保护 |
| 人工确认入口 | 原版非结构化成功输出仍可进入有时效、准确设备的官方人工确认流程；不声称已取得兼容目录，不自动答复官方确认；过期、离线、错误、锁定与明确失败不能进入 |
| 旧更新提醒 | 新的准确设备目录失败撤销较早的可用提醒，并记录失败时间阻止旧成功回复复活；原成功版本及时间只保留为历史，后续明确成功检查可恢复提醒 |
| 完整页面流程 | 从设备入口打开更新、切换设备、检查成功后再失败、关闭重开、重复点击、离线与晚到回复均使用真实页面及隔离 HTTP 替身验证；诊断、参数、记录导出同时走正常、失败与恢复流程 |

一次单独授权的官方只读检查成功读取到硬件版本 1.0.0，命令正常退出且标定资料哈希未变；未再次查询设备、刷写固件或启动实物动作。设备当前固件 1.0.4 与公开版本号相同，不足以证明该硬件适用或已是最新版本。官方兼容目录返回的404尚未消除；公开文档、发行说明与静态程序字符串不足以判断是客户端映射还是服务端目录记录问题，不能猜测固件或绕过兼容检查。

最终全量隔离软件回归2265项，0失败、0错误、2项环境跳过，测试前后Python源码一致。非作者独立执行16项后端测试、37项UI核心检查、21项入口保护和24项通知时序检查；范围有重叠，不相加。交叉复查发现的旧提醒残留、人工确认入口受阻及核对按钮请求不一致均保留改前复现，修复后再次核对。

软件回归、真实页面替身复查、实际安装载荷与资料保护结果分别保留于外部交付清单；合成页面与子进程测试不等于实物升级、标定或遥操作通过。本轮按用户要求直接更新本机同一软件并同步现有源码分支，不上传新的安装包。
