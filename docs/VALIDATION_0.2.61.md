# 0.2.61 日常操作与异常恢复

按连接、更新、人员标定、虚拟预览和实机跟随检查组合流程，再用不同失败位置和操作顺序独立复查。设备、官方进程、SDK 传输及在线服务由隔离替身提供；页面使用实际 HTML、脚本和样式，通过真实回环 HTTP 服务执行。没有为测试接入真实手套、刷写固件或启动实物动作。

## 本轮问题与处理

- SDK 更新在取得维护占用后被空闲检查拒绝，如果释放占用也失败，原实现会遗失返回前保留的令牌，导致同进程无法再核对恢复。现在保留准确令牌和结果未知状态；只有本次启动能证明尚未派发工作线程、原占用记录完整一致时，明确核对才能释放。线程可能已经启动、记录变化或重启恢复的情况仍须证明原进程退出。释放再次失败继续保留原记录，不能显示完成或自动重试。
- 覆盖已有人员标定前，保留官方完整档案导出并核对身份、文件摘要和内容。备份失败不启动覆盖。取消、采集失败、启动失败和成功覆盖均保留原档案；恢复使用原版官方导入确认和后续读回核对，不能自动回答确认或仅凭退出码认定恢复完成。
- 标定或恢复的工作线程、输出线程或原生进程构造失败后，保留准确启动身份和备份。进程退出与占用释放分别核对；未知私有 Job 只能通过原归属明确结束后重试。导出过程中取消且尚未启动采集时显示已取消，保留已完成的备份；恢复退出尚未确认时，公共状态和桌面退出保护继续生效。
- 中等宽度的标定工具条为设备名称及编号保留完整一行，准备表单保持单列并居中。遥操作来源与型号标签的字号统一调整。窄屏正在跟随或停止结果未知时，原操作栏移到来源字段前，视觉顺序与键盘顺序一致；宽屏和已停止时恢复原顺序，保留原控件节点及焦点。

## 操作链与失败顺序

| 流程 | 本轮软件检查 |
| --- | --- |
| 标定后继续使用手套 | 实际官方结果解析、导出、导入、模型归属验证、绑定保存、桥接与手套工作线程；准确地址超时、错误序列号、旧模型、重复打开及显式重试 |
| 虚拟预览至实机跟随 | 执行实际 `paired_hand_worker`、反馈工作线程及 `GloveMotion`，仅帧、SDK 端点和传输替换为模拟信号；预览不启用，明确跟随后以反馈姿态为起点，沿现有速度参数限幅发送 |
| 跟随异常与停止 | 官方 Warning 仅记录、停止等级故障停用、手套信号中断、手反馈中断、浏览器控制续租过期；信号回来只恢复预览；停用应答失败保持未知，拒绝开始或解除配对，明确停止重试后才恢复 |
| 维护失败恢复 | 已连接时读取版本、明确更新的空闲保护、启动前占用释放失败、线程启动失败、准确占用恢复、再次释放失败与下一次更新；原会话及模型资料保持 |
| 备份导出与恢复 | 实际 Controller 和 Handler 导出完整 ZIP；错摘要、错用户、Default、同名不同 ID 及坏 ZIP 拒绝；原版默认 No 结束仍未确认，明确恢复后全量读回才确认；释放失败、关窗保护、明确结束重试、导出中取消及下一次新标定 |
| 页面与键盘 | 中英、1366/960/390 宽度及 125% 的等效 CSS 视口；已有人员的覆盖确认、新增人员输入、两种遥操作模式、未知停止状态、明确开始与暂停；重复状态刷新不重排节点，窄宽切换保留焦点 |

原失败记录与测试夹具修正分别保留。模拟信号检查不是物理仿真；测试端点对发送位置提供合成反馈，不能据此推断真实手指响应、碰撞效果、网络稳定性或长期连接性能。125% 检查采用等效 CSS 视口，不冒称执行了系统或浏览器原生缩放。

非作者检查中曾发现真实备份导出路由缺少摘要模块导入，实际请求失败；窄修后重新执行同一请求，核对服务端 ZIP 字节，并继续完成恢复和取消后的新标定。恢复被严格排除在新标定成功与已连接设备的判定之外，不能据恢复结果自动启动遥操作。旧会话、旧控制代次及旧租约另外以不同操作顺序复查，不能影响新会话或延长新一轮跟随。

本轮不触发浏览器原生下载，不调用 IDM，也不改变其设置。备份导出检查使用代码读取实际 HTTP 字节，保存到隔离目录核对 ZIP 和摘要；页面下载链接另核对，不把代码保存称作浏览器下载验收。

完整源回归、独立复查、包内代码与页面载荷、本机安装后的版本和资料保留，以及 Git 源码同步结果保存在外部交付清单。源码版本与本机构建不代表已公开发布安装包。

最终 Python 源回归执行 2552 项，失败和错误均为零，运行期间源码未变化；其中 3 项跳过分别因缺少未部署的原实物记录、Linux 专属文件锁条件、当前系统不允许创建测试符号链接，不能计为这些环境已验收。标定邻域另有 296 项及 16 个人员、左右手组合检查，具体操作链与独立记录另列，不能仅用总数代替流程结论。
