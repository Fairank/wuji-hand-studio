# 设备首页与工作台模式（0.2.26）

0.2.26 使用“设备”首页，以及简单、完整两种界面。它们使用同一个工作台、设备会话和设置，不是两个软件版本。本文说明本版的使用方式；软件验证范围见 [0.2.26 验证记录](VALIDATION_0.2.26.md)，实机设备另行验收。完整范围见 [用户要求与验收清单](REQUESTS_AND_ACCEPTANCE.md)。

## 设备首页

没有指定页面时，工作台打开“设备”，也可以从侧栏返回。首页使用紧凑的设备列表，撤回之前的欢迎大卡片、黑色大按钮和手绘手形。

- **最近连接**在左侧：只来自实际接入事实，按设备编号去重，最多12条，保存在本机。扫描发现本身不写入连接历史；历史记录也不代表当前在线。只有本次重新检测到且可用的记录才能选择，选择后仍需明确接入。
- **当前设备**在右侧：使用统一发现列表，区分灵巧手与手套，先选实际设备，再选择需要的功能。页面可见且会话允许时每5秒自动扫描；可关闭“每5秒自动扫描”，也可以点击“扫描设备”。自动扫描偏好在本机保存。隐藏页面暂停自动扫描，已有扫描不重叠，已占用会话不会因扫描被打断。
- **选择动作**进入灵巧手展示，无需先接设备即可浏览动作和预览。

首页与“连接与校准”共用当前发现列表，不维护第二套设备选择。发现、选择和实际连接是不同步骤；打开页面不等于接入数据，也不会自行连接第一台设备。具体选择流程见 [设备发现与选择](Device-discovery.md)。

本版页面、按钮、连接状态及服务端可见提示的中文设备名称统一为“灵巧手”。顶部的 Hand、Glove 继续表示各自的官方产品类型。

## 单手与多手在同一个入口

侧栏只保留“灵巧手展示 / Hand demonstrations”，进入后用“单手 / 多手”分段选择。简单、完整模式都能使用多手，不需要为了双手展示切换界面模式。

单手保留节目单与运行详情，多手保留工作区选择、管理设备及停止入口。两个页面复用原来的控件和会话，切换不重建画面、不清空输入，也不开始、暂停、停止或连接设备。多手页面仍在原来的工作区流程内，侧栏保持选中“灵巧手展示”。

分段选择支持左右方向键以及 Home、End；选中底板使用已有的滑动过渡，系统或软件的减少动态效果偏好会生效。

## 顶部 Hand 与 Glove 分开使用

顶部现在分别显示 **Hand** 和 **Glove**，不用先回连接页寻找另一类设备。

未接入时，“接入”进入按设备类型筛选的统一目录，让你按编号选择实际设备；不会盲连或断开另一类设备。手套已有 SDK 会话时，“查看”返回该会话的设置；官方 Viewer 已经拥有手套时，则返回官方画面。

有相应身份核对信息后，名称才补充可确认的代际与左右手。无法确认的项目保持通用名称，不能根据正在展示的模型就判断真实设备。

手套的两种状态分别说明：

| 状态 | 代表什么 |
| --- | --- |
| SDK“数据中” | 当前 SDK 手套数据通过新鲜度检查 |
| SDK“等待数据” | 会话存在，但当前没有有效的新鲜数据 |
| 官方“画面运行” | 官方 CLI / Viewer 会话在运行；CLI 未报告持续数据新鲜度 |

画面运行不等于反馈持续在线，也不代表标定完成。停止与断开仍由拥有设备的会话处理。

## 简单与完整怎么切换

首次默认使用**简单模式**。侧栏底部的“简单 / 完整”可以随时切换；“设置 → 外观 → 工作台模式”提供同一个偏好入口。选择保存在当前工作台的本机偏好存储中，重开后读取；本机存储不可用时仍能切换，只是不保证保存。

简单模式突出设备首页、灵巧手展示、连接和设置，其中灵巧手展示包含单手与多手。完整模式展开参数、设备工具及更多高级配置。已有高级页面仍可保持当前内容，不会因切换模式强制结束任务。

切换只调整界面显示，不重建已有设备控件或清空草稿。连接、动作播放和当前会话继续使用原来的状态；切换本身不连接设备、不开始标定、不使能电机，也不发送动作或停止命令。需要停止动作时，仍使用动作或会话中的停止入口。

## 磨砂恢复与系统行为

Windows 的系统外观变化可能让 pywebview / WinForms 覆盖已经设置的 DWM 背景类型，表现为回到工作台后仍保持实色，需要重新拨动透明开关。0.2.26 保留你最后请求的透明偏好，在窗口激活或还原、句柄重建、主题、桌面合成及相关系统变化后重新应用；页面恢复可见时也会重申偏好。

原生恢复器用 **150ms** 合并密集事件，普通拖动和连续改变窗口尺寸不会逐帧重设材质。界面按顺序处理材质请求和恢复通知，以 `recovery_count` 排除落后的异步结果，避免新选择被旧结果覆盖。你选择关闭透明后，后续事件仍遵循关闭状态，不会重新打开。

这是一套有限事件响应，不增加后台轮询或桌面采集，不切换窗口焦点，也不修改 Windows 的主题、透明效果或其他系统偏好。微软要求桌面合成状态变化后重新应用窗口框架配置，相关接口见 [DwmExtendFrameIntoClientArea](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/nf-dwmapi-dwmextendframeintoclientarea)。

**失焦后变实色不一定是故障。** 微软说明背景 Acrylic 在桌面窗口失去激活状态时会退为实色；系统关闭透明效果、高对比度或节能等状态也可能影响显示。工作台不会强行覆盖这些系统规则，因此不承诺窗口未激活时仍然透明。返回窗口或相关系统事件发生后，会按当前偏好重新应用，无需重新拨动开关。[微软 Acrylic 行为说明](https://learn.microsoft.com/en-us/windows/apps/design/style/acrylic)

对工作台自有隐藏窗口已检查真实 DWM 配置、该窗口自身的消息、关闭透明选择和卸载路径。这些检查确认配置与恢复生命周期，不代表实际屏幕上的透光质感已经完成视觉验收。

## 声明放在哪里

左下角和工作区底部不再反复显示“非官方个人展示工具”。“设置 → 关于”及桌面菜单中的说明仍保留，README 的非官方身份说明、许可证和第三方来源声明也保留。

本版沿用同一安装身份和用户数据目录。模式选择不会迁移标定、替换设备参数、改变 CLI / SDK 来源或安装 Studio。

## 语言与默认反馈

语言切换放在“设置 → 外观 → 语言”，顶部不重复显示。英文侧栏为完整单词保留宽度，页面随侧栏一同调整。简单/完整选择使用同一个移动底层，按钮不叠加另一块选中胶囊。

轻柔回弹直接用于按钮、分段选择及页面过渡，没有单独的“试一下”演示设置。系统和软件的“减少动态效果”仍可立即停用这些界面动效，设备控制不受影响。
