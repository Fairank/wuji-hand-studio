# 0.2.55 官方目录与文件安装后端

前端保持同一设备更新窗口，后台复用官方 HTTPS 目录、官方 ZIP 和官方 CLI 的文件安装模式。目录查询与包准备不连接实物；只有用户明确打开官方安装时，才重新确认所选设备、取得共享维护占用并打开原版人工确认。

## 数据与操作边界

- 手套目录直接请求官方 `/v2/firmwares?sn=...`，区分目录版本、原设备版本及各自观察时间；目录结果不生成“硬件已兼容”或原在线升级权限。
- 目录格式、下载路由、大小、SHA-256、ZIP 成员、manifest、固件及调试附件均校验。只发布完整验证的包；失败保留损坏原件，显式重试使用新目录，活跃或未知写入的包不删除。
- 安装只使用后台一次性凭据绑定的包，界面不能提交任意文件路径。凭据绑定准确序列号、版本、包摘要、到期时间及维护占用；开始前重复校验包与官方 CLI 身份。
- 使用 `upgrade --sn <SN> --file <official.zip>`，保留官方提示，不添加 `--yes`、`--force`，不接受裸 BIN，不修改包或伪造硬件版本。
- 文件模式写后核对通过官方 `serial_number`、`firmware_version` 资源，要求准确设备、CLI 身份和标准字符串结果。未知格式、版本不符或读取失败不表示升级成功；读取进程退出不明时保留原占用。
- 写入开始意图在启动前持久化。只有明确尚未启动的准备过程可在核对后释放；可能已启动的进程、读进程或释放状态不明时不能重开另一写入。

## 验证范围

最终全量隔离软件回归2322项，0失败、0错误、3项环境跳过；测试前后Python源码一致。相邻回归及实际页面阶段有重叠，不与全量数量相加。最初全量回归的3个错误来自旧测试宿主缺少新增目录接口，补齐测试宿主后重跑，并保留原始失败记录。

使用完整源页面、实际本机测试 HTTP、真实隔离锁文件与 ZIP，以及设备、官方进程替身，验证正常、重复、失败、中断、显式重试、旧回复、设备切换和恢复流程。独立复查使用不同故障位置，保留修前与修后记录。最终软件回归、页面阶段、实际本机安装载荷及资料保留结果见外部交付清单。

本轮没有连接手套、运行真实设备读写命令或刷写固件。目录与 ZIP 完整性不等于数值硬件兼容验证；官方文件模式的实际设备检查、提示和写入仍需设备接回后验收。尚未实测的 JSON 变体按未知处理，不猜测为成功。当前适配已核实的一代手套扁平 manifest；灵巧手保留原官方流程。

官方服务带硬件版本筛选返回404的事实仍保留。应用提供的是官方支持的文件安装路线与独立版本读取，不宣称修复了官方目录记录，也不把替身流程当成实物升级完成。按用户要求直接更新本机并同步现有源码分支，不上传新的安装包。

官方合同：[CLI 固件升级](https://docs.wuji.tech/docs/en/wuji-cli/latest/firmware-upgrade/)、[参数读取](https://docs.wuji.tech/docs/en/wuji-cli/latest/parameters/)。
