# Windows 0.2.4 折射刷新与自动停止验证记录

## 已验证

- 去除原本的 50 毫秒采集与界面轮询上限；Windows 按当前显示模式请求 60–120 Hz（16/8 毫秒），并在静止时等待新画面。采集请求不等于实测帧率。
- 独立逻辑测试覆盖 60/120 Hz 正常运行、一次大于 31 毫秒停顿及持续低于 60 Hz 后停止；采集统计只对连续运动帧计速，静止时没有新画面不算低帧率。持续显示监测仅在运动时运行。
- 浏览器合成帧验证：折射开启时绘制一条玻璃边；注入一次 45 毫秒主线程停顿，界面报告停顿、取消勾选并移除折射画布，没有控制台错误。测试没有截取真实桌面，也没有连接机械手。
- 维护检查接口分别记录显示循环、实际呈现和原生捕获回调频率，不能将其中一种当作另外两种的实测值。
- 本机主显示器报告 165 Hz，采集请求按上限设置为 120 Hz；合成 4K 边缘编码的 25 次离线样本 p50 3.78 毫秒、p90 4.30 毫秒。该结果不含屏幕捕获、WebView 桥接及实际呈现，不能推出整条链路达到 120 Hz。
- 380 项 Python 测试通过，1 项按原条件跳过；独立 JavaScript 节奏测试通过。更新后的合成页面中，连续变化正常开启、静止 750 毫秒保持开启、注入 45 毫秒主线程停顿后显示 50.8 毫秒并关闭，画布被移除，无控制台错误。
- Windows 0.2.4 安装器 SHA-256：`10a45166752120a8e7e325000dc15af57bcbc6d3daea3e8e804c7fb2760fc119`。已完成安装、安装后离线自检及桌面检查；版本显示 0.2.4、错误列表为空、手保持断开。安装时发现并修复 Codex 打包环境的应用数据目录重定向误判，新版本的更新预检接口已验证可用。

## 尚未通过的现场验收

- 真实 Windows 桌面背景运动时，折射能否持续保持 60–120 Hz 新画面尚未实测。当前 JPEG/base64/WebView 桥接架构可能在较高分辨率下自动停止；不能把这版称为已达到苹果系统材质性能。
- 真实显示器 60/120 Hz、窗口移动、跨屏及休眠恢复场景需要实际测试。折射只影响外观，自动停止不会向机械手发送动作命令。

实现借鉴 [Apple 对 ProMotion 可变刷新与按需绘制的官方建议](https://developer.apple.com/documentation/quartzcore/optimizing-iphone-and-ipad-apps-to-support-promotion-displays)，没有使用或声称移植苹果的系统材质代码。Windows 端只请求刷新节奏，实际帧率必须单独测量。
