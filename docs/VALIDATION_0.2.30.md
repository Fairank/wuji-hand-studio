# 0.2.30 原版 Human TTY 单一流程验证记录

更新：2026-10-22。本记录区分源码软件检查、独立界面验收、打包安装和真实手套标定。完整Python结果与独立界面23个唯一场景的最终通过结果已确认。本随包文档不写安装包自身摘要，也不提前宣称本版覆盖安装或公开发布完成。

## 本版修正的问题

0.2.29将Viewer与标定入口放进同一个官方CLI工作区，但仍先要求用户在工作台创建/切换用户、选择侧别和确认覆盖，再进入原版终端。用户指出仍有两套流程，这个问题确实存在。Viewer欢迎页和设备画面本身也不能执行手型标定。

0.2.30改为上方一次选择实际设备SN，「查看画面」与「开始标定」使用同一个显示区。默认Windows原生模式直接交给固定官方CLI 2026.10.12的Human TTY：创建/切换用户、实际绑定用户的Default保护、覆盖确认默认No、六步固定彩色ANSI指导和结果流程均由原版提供。工作台不重复要求个人档案、侧别或覆盖表单，也不替用户输入确认。显示的是原版终端菜单和图示，不是完整 Studio 图形界面；用户直接跟随提示操作，无需编写源码。

原版能力依据固定公开提交 `a54280f4a6d4cf43b37f551c35e9db04b6cf476d` 的 `skills/wuji-cli-calib/SKILL.md`。该说明明确区分Human TTY与JSON/JSONL：前者可由原版提示建换用户，后者仍需事先核对命名用户与覆盖授权。实际采集后的模型归属以设备绑定用户和本次官方输出为准。

## 保留的控制边界

- 启动必须由用户明确操作，使用统一目录中已选、仍有效的精确手套SN。原生路径复用共享目录，不在启动标定时强制另扫、不改选其他设备。
- 启动仍要求所有相关工作区闲置；Viewer、手套预览或遥操作须由用户明确结束，不隐式切断会话。
- 原生入口为独立 `start_human(serial, expected_side=None, timeout=900)`，不接收用户或覆盖参数。受Job约束的内部worker只接收token、SN、目录已知侧别或auto、超时。
- worker核对精确Job、token、宿主身份、marker绑定的SN/侧别和固定CLI版本，并以官方参数的严格 `left` / `right` 值核对实际侧别。未知侧别不靠编号推断，调用方不能覆盖目录所报侧别。
- 官方命令只指定同一SN和超时，不传JSONL、用户、侧别选择或自动覆盖选项。用户和覆盖决定保留在原版交互中。
- `ready`只回传已核对的实际SN与侧别，工作台不推测终端内当前用户。退出0仅记 `session_ended`；退出5、错误、取消、未知退出及未确认清理不能显示为新模型成功。
- 原有取消、EOF、异常宿主退出、精确Job恢复和清理门禁继续保留；失败不自动重试。旧非原生JSONL路径的Default、命名用户、模型状态、侧别和覆盖同意检查不放宽。
