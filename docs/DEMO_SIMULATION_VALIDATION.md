# 路演流程维护：模拟验收记录

2026-11-05，接续 11 月 4 日的排查。基线为 `feature/hand-workbench-0.2.1` 的 `182c4d4`，程序版本仍为 0.2.78。本文件记录后续源码补丁的验证，不代表安装包发布或本机覆盖安装。用户明确要求在没有实体设备时使用 SDK／CLI 接口替身及合成反馈验收单手、手套和多手流程。

## 本轮复现和修复

| 触发条件 | 修复后的行为 |
| --- | --- |
| 发现了可用的手，但广播未提供左右手，或上次预览是另一代／另一侧 | 展示页允许选择本次发现的手。明确连接仍走 `WujiDeviceUse → WujiConnectionSwitch → ConnectionSwitch`；型号只作为连接意图，实际模型仅依据准确设备的 SDK 身份同步。选择、刷新和切换预览型号不连接或启动设备。 |
| 连接点击等待期间，另一个用途接管了会话 | 展示页与普通设备入口都保留点击时的 owner context。两次状态读取之间变化也会拒绝旧请求，用户可明确重试；只读查看保持零连接请求。 |
| 统一设备页已经发现多只手，多手入口却仍为空 | 普通多手入口投影同一设备目录，明确扫描复用现有 `device_inventory_scan`。自定义地址保留原有路径；已占用、冲突、过期或未知工作区状态不能授权重复接入。 |
| 启动 RPC 尚未返回，旧空闲反馈到达或超过三秒 | 准确设备、会话及请求的待确认归属继续保留。控制端处理完启动或拒绝后回传确认；旧空闲帧不能清除请求。发送结果不明和磁盘记录失败分别处理。 |
| 启动旧回复、错误、心跳失败晚于新动作 | 旧回复不再发送无归属的自动停止，也不清除新请求、lease 或错误提示。服务、设备、会话及公开控制标识参与核对。 |
| 套用已存标定时，读取 binding 期间用户取消 | 最终 binding、tuning 和视图写入在原会话及 attempt 的保护内重新核对；已接受的取消、配置变化或替换会话不能继续写入。 |
| 固件工具因 pywinpty 缺失／版本不符而在创建子进程前失败 | 可证明未启动的失败保留为未启动，并允许准确恢复及明确重试；任意启动异常及启动后的证据失败仍保留未知状态、原进程和维护占用。 |
| 设备停用未确认，或官方画面／标定／用途切换仍占用资源 | Windows／Mac 网卡配置拒绝执行；Mac 一代手返回 USB 状态，不进入以太网配置。 |
| 一代控制端提供 `requested_hz` 而界面读取 `target_hz` | 目标频率兼容两种字段，缺失测量值显示不可用标记，不再显示 `undefined Hz`。 |

没有新增连接管理器、设备扫描服务、标定算法或电机控制路径；保留现有布局、磨砂样式、导航和动作参数。

## 三条演示链的证据

| 流程 | 本轮软件证据 |
| --- | --- |
| 单手快速接入与展示 | 完整实际页面配合合成 API，验证未知左右手 Hand 1 连接后识别为右手、等待期间换预览型号、错误设备身份、失败后明确重试。正确连接只发送一次共享切换请求，重试由第二次明确点击发起，没有动作启动。实际 SDK worker 循环另用替身验证一代／二代启动确认、拒绝及最终退出。 |
| 标定、套用与遥操作 | 实际 Controller、ConnectionSwitch、保存档案与接续函数配合替身；事件屏障覆盖读取时取消、获取写保护前取消、旧回调、替换配置／会话和明确重试。既有标定、映射、SDK 反馈、跟随与退出用例纳入完整回归。 |
| 多手协同 | 实际 HTTP 服务创建两个独立离线原生模型子进程，验证配对预览自然完成、暂停／继续、手动停止及界面心跳过期。两个 Controller 在各检查点均无设备身份、电机未使能、停用记录为空；仅清理本次创建的两个子服务。实际协调器与两个替身 Controller 另验证启动、同步提交及准确 token 停止。 |

## 完整检查

使用 Python 3.12.7、Node 24.22.1，执行仓库统一入口：

```powershell
python scripts/run_review.py
python src/desktop.py --self-check --render-check
```

- Python：2869 项，失败 0、错误 0、跳过 3；跳过不作为验收通过。
- Node：269 项，全部通过；检查器自身 8 项及既有连接命令 11 项通过。
- Python AST 416 个文件、JS 语法 92 个文件通过。
- 检查期间受检源码摘要无变化；被拒绝的真实 SDK、默认 SDK 数据或非回环网络操作为 0。
- 四种原生模型加载、58 个动作目录、离线渲染及 TLS 自检通过；`hardware_connected=false`。
- Windows 全新隔离目录发现的路径夹具、SDK 回执夹具、打包前资源夹具和 UTF-8 日志问题已复现并修正。打包生产校验没有删除；检查器仍保留失败返回码和原始日志。

页面使用 Playwright 与本机 Edge，视口 1440×1000；Browser 插件未提供。页面标题、非空内容、样式、实际下拉选择／连接／重试及控制台错误检查通过，没有框架错误遮罩。截图中的设备回复为合成值；反馈画面正确拒绝把其他会话的旧帧当作新设备数据。原始失败、最终摘要、截图与非作者换顺序复查保留在本机隔离验收目录，不随源码上传。

## 复查与边界

不同作者交叉复查了共享入口、SDK 身份、启动记录持久化、迟到确认、取消锁顺序、固件预检进程归属，以及多手目录中的 CLI／SDK 占用。复查发现的旧 owner 接管、已占用设备重复新增、只读查看被过严拦截和旧暂停错误覆盖均已修复后重验。

桌面端与控制端源码须配套更新。内置环境沿用现有版本化源码同步；外置 Linux／SSH 控制端也须同步新控制程序。旧控制端若拒绝启动又不提供请求确认，桌面端保留待确认状态，不用超时或重新连接清除它。

本轮没有执行真实固件刷写、物理标定、实机动作、真实插拔或场地网络测试；也没有构建／安装新版程序或开启远端工作流。合成固件回复和 SDK 替身不是实体固件仿真精度的证明。用户选择的三条模拟演示链已获得上述证据，不能由此承诺任何物理现场绝无故障。
