# 修改与交付验收

每项修改都需要完整流程验收。测试总数不能替代本次操作链的证据，也不能将合成检查称为真实设备验收。

调试默认使用已安装的 `systematic-debugging`、`test-driven-development` 和 `verification-before-completion`，页面再配合 `frontend-testing-debugging`。技能来源为 obra/superpowers 的固定提交 `2ce8aa15d05bd57213e6f746f953aafb7ded7a8b`；技能不能替代以下项目约束，也不增加设备、上传或发布授权。无需等用户再次说“检查”才应用。

每次审查先按当前调用链列出入口、状态持有者、持久资料和外部副作用。对本次受影响的状态转换，主动选择不同的交错顺序：等待中换页或换服务、旧读晚于新写、操作已生效但回执失败、退出失败后换一种明确恢复入口。使用事件和有界等待控制时序，不能仅靠随机延时碰运气；发现同类代码后扩大到共享实现的相邻入口。保留失败复现，再作最小修复，非作者使用另一种失败位置复查。构建或总回归通过不能代替这些流程。

1. 列出入口、共享实现、状态归属和外部资源。先复现，再排查相同写法和相邻入口。
2. 每个受影响流程检查正常完成、重复操作、失败、中断及显式重试。异步操作额外检查旧回复、换页、关闭重开和离线后的行为。
3. 修复后重走原失败过程，确认原资料、旧会话和不属于本次操作的资源保持；退出或保存不明时不能显示成功。
4. 由非作者独立审查，选择不同的失败位置和操作顺序。发现新问题后继续修复、补回归并复查相关入口。
5. 在隔离资料、网络、设备和进程替身中执行软件验证；普通合成集成子进程单独记明。设备发现保持只读，不为测试自动接入、确认固件写入或启动实物动作。
6. 根据实际改动执行必要回归与打包核对。交付时核验安装后的版本、程序和页面载荷、用户资料保留，以及源码同步结果。
7. 分别记录实测、合成、跳过和未执行范围。检查日志、原始失败与修正后的证据保留；不能因为某一轮未发现问题而承诺没有任何缺陷。

## 连接逻辑保持集中

普通设备用途选择沿用 `WujiDeviceUse → WujiConnectionSwitch → ConnectionSwitch`，由现有官方 CLI 或 SDK 适配器执行。不要在各页面新增独立连接管理器、重复扫描并打开、后台重试或另一份在线状态；实际归属由同一 `owner()` 读取已有会话事实。设备选择及每五秒发现保持只读，明确用途选择才申请转接。同用途复用会话，跨用途先确认旧资源退出，再打开准确新用途。

已存标定导出、校验和 SDK 导入属于资料转交，不持有独立设备连接。新标定继续通过现有 `calibration_begin` 与共享工作流锁释放原会话。旧兼容 API 不作为普通页面的新入口；调整时先查调用者，避免为简化表面而破坏既有清理和取消合同。新增功能优先接入这些现有入口，每处只保留一份职责。
