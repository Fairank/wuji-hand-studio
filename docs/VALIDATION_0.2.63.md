# 0.2.63 新顺序复查

本轮重新执行软件流程，没有将上次的验收清单重读当作新验收。检查现有实现的锁顺序、服务与请求身份、已生效但回执失败的操作，以及失败退出后的另一种明确恢复入口。原始失败、修复后流程、测试夹具错误和非作者复查分别保留。

## 复现及修复

- 新增或切换标定人员时，原实现持有标定运行锁再读取 Controller，状态读取则按相反顺序拿锁，存在互相等待。改为共享入口串行、短运行锁检查，再释放运行锁进行状态核对和官方人员操作。
- 官方人员操作已写入但返回报错时，旧缓存可能继续显示原人员；迟到的旧读取也可能重新写回该缓存。人员变更前后均失效元数据，并在读取提交和返回前核对内部代次及运行身份。迟到读取只报告尚未核对，不能覆盖新结果。没有更改官方用户或标定协议。
- 退出失败后改点明确回退，回退成功仍保留关闭标志，自动检查线程持续跳过。成功回退现在恢复原线程的工作状态；失败、错占用或未知结果仍不解除暂停，偏好不变。
- 报告页在生成支持包时服务断开并重建，旧请求会令新服务按钮持续禁用。等待状态现归属原服务和准确请求，旧成功、失败和收尾不影响新操作。
- 原日志导出只判断 ZIP 容器格式，内部文件 CRC 损坏仍可能显示完整成功。发布官方附件前检查内部文件；失败保留简报、官方输出和收取错误，损坏附件不可下载，明确重试生成新目录且不覆盖旧结果。

## 实际执行范围

使用实际 Handler、Controller、标定与更新服务、文件协调、SDK 控制工作线程和完整源页面；仅将官方网络、进程、设备端点及模型输出换成严格替身。人员新增、覆盖、多个档案及左右手保存、恢复后读回、标定接续，分别检查正常、失败、取消与重试。组件及固件流程检查兼容目录失败、包字节校验、进程失败、明确重试及准确版本读回；软件更新检查下载、校验、取消、旧安装回执、未知结束及精确完成证据。实物写入没有执行。

本轮新的模拟信号流程包含手套断流后停用且不自动恢复、手反馈断流、旧跟随凭据拒绝、SDK 关闭拒绝后保留原用户至明确重试，以及新会话拒绝旧断开。非作者另在持续新鲜骨架与心跳下模拟停用回执失败，验证仍保留未知状态、不继续发送动作，并通过明确停止再解除配对。所有所属工作线程最终退出，模型未重复导入。

页面采用代码 Playwright 和隔离回环 HTTP，检查宽窄窗口、中英、选手与模式切换、人员表单、更新弹窗和报告按钮。支持附件通过代码 HTTP 保存并校验 ZIP、原字节及旧资料；没有启动浏览器原生下载或 IDM。Browser 插件不可用，使用已安装的无头 Edge。

## 默认方法与边界

采用固定来源的 `systematic-debugging`、`test-driven-development`、`verification-before-completion`，配合已有页面测试技能，默认按当前状态链主动构造交错顺序。技能是方法约束，不表示能保证没有缺陷，也不增加任何设备或外发授权。

真实手套与灵巧手连接、固件刷写、真实标定采集和实机动作仍未执行。合成检查不证明硬件时序、温度、运动质量或长期网络稳定性。最终软件回归、构建内容、本机安装后的文件及资料保留、Git 同步结果由本轮外部交付清单分别确认。

首次终端全量测试进程未形成完整汇总，保留原日志但不计为通过。另一次以无控制台解释器运行，在直接调用原生工作线程的测试中缺少所需输入管道；该次错误也保留。最终回归采用独立隐藏的控制台 Python 和明确输入输出管道执行同一套源码测试，按完整汇总判定，不修改生产逻辑、跳过测试或放宽断言来处理这些执行差异。
