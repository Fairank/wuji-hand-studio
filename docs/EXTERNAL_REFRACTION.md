# 外部背景折射（实验）

Windows 菜单增加独立的“外部背景折射”开关，每次启动默认关闭。开启后使用 Windows Graphics Capture 读取工作台所在显示器，排除工作台自身，然后立即裁成四周窄边纹理，在本机 WebGL 中按曲面位移重新采样。这不同于系统 Acrylic 的背景模糊；也不是苹果的系统 Liquid Glass API。

操作系统捕获接口会提供显示器帧，应用仅保留边缘裁切结果；不写入文件、不上传、不开放 HTTP 背景图片接口。Windows 会显示捕获指示。手动停用或窗口关闭时停止会话；最小化时暂停捕获，恢复后继续；“减少透明效果”会停用折射。窗口跨两个显示器时回退到系统背景，完整移动到单个显示器后可恢复。捕获权限或显卡暂时不可用时保留开关并重试。

代码检视截图会隐藏折射纹理，以免将用户其他应用的内容带入开发记录。已通过生成参考图案的着色器检查、四周裁切测试，以及仅捕获本工作台不透明窗口的 WGC 接口检查。**没有采集用户桌面做完整外部背景效果验收**；此功能保持实验标记，尤其是多屏移动、HDR 和受保护内容。

0.2.4 借鉴 ProMotion 的按需绘制原则：按所在显示器的模式请求 60–120 Hz 捕获，新画面到达后才编码边缘、上传纹理，并在下一次显示刷新时绘制。静止时原生读取最长等待 250 毫秒，网页不循环重绘；显示节奏监测只在连续运动时运行。单次超过 31 毫秒的绘制/显示停顿，或连续运动帧的采集、呈现低于 60 Hz，都会自动关闭效果。维护接口分别报告目标、实际采集、实际呈现和绘制耗时；目标刷新率不代表验收帧率。现有 JPEG/WebView 路径尚未完成真实动态桌面 60–120 Hz 验收。

0.2.5 按用户要求取消上述性能自动关闭：停顿和低帧率仍作为诊断提示，折射开关保持开启。窗口最小化时停止实际屏幕捕获，恢复后自动继续，不因旧帧序号反复空轮询。暂时采集或 WebGL 中断会尝试恢复；手动关闭、关闭软件及系统减少透明效果仍停止捕获。

0.2.6 修复拖动窗口时每次位置变化都销毁并重建 WGC 捕获会话的问题。同一显示器内移动和调整尺寸只更新裁切位置，跨显示器或显示模式变化才重建；移动期间提高位置采样频率，网页在矩形未变化时不重复写四块画布的布局。测试验证同屏移动/缩放保持单一会话且新帧取样随位置变化，跨屏切换才启动第二个会话。真实桌面拖动帧率、120 Hz 稳定性和苹果系统材质的视觉等效性仍未验收。当前四张 JPEG 经 WebView 桥接和解码，仍比系统原生 Acrylic 链路重。

实现依赖：[windows-capture](https://github.com/NiiightmareXD/windows-capture)、[Windows 捕获排除接口](https://learn.microsoft.com/windows/win32/api/winuser/nf-winuser-setwindowdisplayaffinity)。
