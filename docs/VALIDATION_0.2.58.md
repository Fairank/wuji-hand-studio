# 0.2.58 标定套用与遥操作流程

本次按标定套用、虚拟与实机遥操作、展示页选手的顺序处理。软件流程使用隔离的 SDK、设备、网络及进程替身验证；不为验收重新连接手套、标定或驱动实物。

## 官方能力的沿用

连接、订阅、用户资料、求解和释放使用官方 SDK 接口，连接参数保持 SDK 的原生默认值，没有增加自行设计的网络重连策略。核对依据包括已校验摘要的 2026.10.26 官方 wheel 类型声明和[同版本遥操作示例](https://github.com/wuji-technology/wuji-sdk/blob/v2026.10.26/examples/python/retargeting/1.teleop_real.py)。工作台围绕这些接口处理明确选择、会话归属和界面状态，扫描不会接入设备。

CLI 与 Studio 的公开仓库未提供可对照的内部连接管理实现，不能声称复制了其内部源码或达到相同的实物稳定性。当前启动使用实测姿态和启用确认，保留既有用户的增益、限流与速度设置；这也不是把官方示例的固定启动时长和演示参数直接覆盖到用户配置。

## 标定保存与套用

原接续过程把控制端的一次广播扫描当成手套是否存在的最终结论。Windows 官方发现与 Linux 控制端可能处在不同广播域，导致保存成功后却提示找不到原手套。现在仅在用户明确继续时，读取官方刚发现的准确设备地址并交给原 SDK；没有新鲜地址时仍使用准确序列号，连接后重新核对类型、序列号及左右手。不会猜地址、换另一只手套或自动重连。

成功结果、官方导出与导入、SDK 用户及模型文件使用同一身份和摘要。接入成功与收到有效映射数据分别记录，只有新鲜 SDK 求解输出和准确模型证明一致时，界面才显示“已应用”。这套数据保存在官方 SDK 的用户档案中，并由遥操作加载；它不是一次手套固件刷写。软件对本地模型文件和求解输出的核验不能替代对实物动作效果的验收。

多用户与左右手档案分别验证。给已保存右手的用户新增左手、反向新增右手，以及更新其中一侧，不应丢掉另一侧或其他用户的资料。含另一侧旧数据的资料包在导入前拒绝，使用官方完整导出、预览和导入，不自行裁剪重组官方包。保存记录先落盘，导入后校验各组件；导入已确认而记录提交失败时，可由用户明确重试，经官方重新导出核对后恢复记录，不重复导入。未知导入结果或外部改动不会被当成成功。

连接到错误设备后，若关闭句柄失败，原工作进程保留准确句柄和租约，显示可重试状态。明确重试结束之前不能自动恢复用户、释放占用或连接新设备。

## 虚拟与实机遥操作

标定完成后提供“虚拟遥操作”和“遥操作”两个入口，复用同一个 SDK 会话和模型。虚拟入口显示已有映射预览，使用已有官方模型与几何约束；未收到数据时显示等待状态。切换页面不会重新导入、接入设备或开始跟随。

实机入口保留明确的目标灵巧手选择、连接、开始跟随、暂停和断开。虚拟入口不接受配手或跟随指令。若实机原本在跟随，切到虚拟页面仍保留停止入口，不把切页伪装为已停止。图像与用户、模型、设备、会话和显示入口绑定，旧实机图不能落入虚拟页面。原有画面尺寸调整继续使用。

## 展示页选手

展示页的型号与左右手属于本页选择，不再要求先到遥操作改变全局型号。目录、模型、播放与导出带同一展示型号；选择本身只读取数据，不接入设备或停止其他任务。各型号的本地预览播放器独立，暂停和停止不能操作另一个型号的播放、节目单、编组或实机。

实机展示由用户选择准确设备并明确连接。启动动作时同时提交展示型号和设备序列号，服务端在实际派发前与已连接设备再次核对；即使替换成同型号同侧的另一只手也必须拒绝旧选择。真实手与预览使用明确的只读画面来源，切换不会停止原任务，也不能继续将旧预览显示为实机反馈。

## 检查与交付记录

连接稳定性另外检查了页面切换、后台可见性、短暂请求失败、SDK 帧积压及旧控制请求。纯手套预览不依赖实机跟随的网页租约；暂时缺少新帧不能被当作 SDK 已断开，也不能借此延长真实指令的新鲜度。已复现的误操作是旧局部停止、断开请求迟到后作用于新 SDK 会话，或同一会话里后一次跟随、重新配手。局部请求绑定会话与控制意图代次，在最终发送前核对；任务视图的归属证明也包含控制代次。“打开手套”和“开始跟随”同样绑定原操作上下文，保留原有 SDK 版本、身份和新鲜度检查。转接过程中仅允许使用准确任务令牌取消当前转换，旧会话请求不能取消新任务；取消已受理与设备已断开分开记录。全局明确停止入口保留。

跟随启动返回准确的租约、会话和控制代次，不由界面猜测。相同控制服务的迟到旧会话、旧代次状态不能清掉新租约；更换服务或离线仍清除本地续约权，不自动恢复跟随。停止、断开和页面关闭只操作当时所属的准确会话。界面收敛不改变控制端的数据过期判断。

慢速接入期间，原界面可能再次显示可连接，第二次打开请求还会令工作进程把原连接资源当作本次失败资源清理。本轮在接入提交后保留准确的进行中状态，拒绝重复打开；旧 ready 状态不能重新放行。工作进程也分别识别本次取得的资源与原有资源，重复预检只返回提示，不关闭原订阅、恢复原用户或释放原占用。实际代码的合成回放确认了原故障及修正后的持续数据流；未借此自动重订阅设备。

现用旧版的一次被动状态读取仍是初次标定接续的扫描否决，不是已连接后的掉线证据。没有据此承诺已定位所有实物断联原因，没有接受回退帧、自动重连、改动网络设置或放宽实机保护。实际长时间连接与网络稳定性仍需接入设备验收。

先复现原失败，再验证正常完成、缺失首帧、错设备、保存失败、退出失败、明确重试、取消、离线和迟到响应。多用户与双侧交叉顺序、会话租约及前端入口另由非作者复查。前端使用完整源页面和代码驱动的浏览器，不调用现用设备。

完整回归、最终源码身份、编译模块及页面载荷比对、安装载荷、本机更新、资料保留与原分支源码同步结果分别保存在外部交付清单。原失败记录保留。没有执行真实刷写、重新标定或实物跟随，不能把软件测试通过称为硬件效果已经验证。
