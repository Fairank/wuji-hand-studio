# 0.2.65 再次模拟验收

本轮从已交付 0.2.64 源码重新执行新的操作顺序，没有将旧记录重读当作验收。使用实际 Controller、HTTP Handler、用途切换事务、官方画面生命周期、资料导入核对、GloveBridge 读取循环、SDK 控制线程及动作适配器。官方设备、SDK、进程和网络边界使用隔离替身，没有接入实物或运行物理仿真。

## 新复现与修复

A 完成右手标定后，明确新增或选择已有右手标定的 B，再打开同一手套 CLI，普通转遥操作仍优先使用 A 的旧接续证明。旧证明只匹配设备与左右手，没有代表当前人员；后续官方导出拒绝，而 CLI 已被释放。原 A、B 资料未丢失，也没有用错模型开始控制，但用户会失去原预览且无法按当前人员进入遥操作。

普通原生用途选择现在在释放前通过已有资料预核对读取当前官方人员及准确 UUID、侧别和模型，不再由旧接续或恢复提示决定人员。已在接收的准确 SDK 会话仍优先复用，明确 SDK 档案参数仍完整保留；用户明确选择“继续本次标定”时保留原运行证明约束。页面同样不把旧原生提示自动填成显式 SDK 人员参数，超时偏好不作为人员身份。修改集中在原用途选择逻辑，不增加连接管理器。

## 本轮流程范围

- 新顺序连续跨 CLI / SDK 目的切换、同用途重复选择和两个准确序列号，记录实际打开、关闭、导入及存活线程；另在次轮新鲜数据前交错旧回调、旧数据、关闭拒绝和取消后的新请求。
- 实际标定人员新增、保存、双侧和覆盖的资料流程，多个档案套用、CLI 往返和导入已生效但本地保存确认失败后的明确恢复。核对当前人员变化、旧读取迟到及取消后新请求，不以同名代替 UUID。
- 模拟手套信号短时抖动、持续断流、网页心跳过期但设备信号持续新鲜、手反馈故障、停用确认失败和旧会话命令。通过实际 SDK 版本检查入口和实际动作适配器检查，仅明确跟随才启用，数据恢复后不自动恢复动作。
- 实际完整源页面从设备目录进入 CLI、标定纯表单、虚拟预览、同侧手配对、模拟跟随和停止，再回 CLI；检查等待时换页和重复点击、离线服务重建、旧回复迟到，以及显示人员与标定是否匹配。

页面采用代码 Playwright 和已安装无头 Edge，仅访问隔离回环服务，覆盖中英及宽窄窗口。Browser 插件不可用，没有桌面鼠标键盘操作、浏览器原生下载或 IDM。严格区分测试夹具修正、真实产品失败和修复后证据；新原始记录保存在仓库外。

最终回归、独立复查、编译内容、本机原位更新后运行文件与资料保留、现有 Git 分支同步分别由本轮外部交付清单确认。本轮模拟不证明真实设备的长时间断联率、USB 或网络切换耗时、温度及实机动作质量；这些仍需接设备验收。
