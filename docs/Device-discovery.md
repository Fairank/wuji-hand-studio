# 发现并选择设备（0.2.25）

“连接与校准 → 设备连接”现在先显示统一设备目录。发现、选中、打开数据流、标定和机械手动作分别进行；选中卡片不会使能电机，也不会自动开始标定。

## 日常怎么用

1. 接好设备电源和数据线，打开设备连接页。页面可见且工作区允许扫描时自动查找，也可以点击“重新查找”。
2. 在目录中按序列号选择实际设备。左、右机械手和手套分别计数；同侧多台设备仍需按编号区分。
3. 选择需要的功能：手套可打开官方画面、设置 SDK 预览或进入标定；机械手可连接反馈。实际动作仍在对应动作页面明确启动。

扫描只读取设备身份。它不会启动官方 Viewer、SDK 映射数据流、标定或机械手动作。处于后台或隐藏的设备页不持续触发扫描；扫描失败会退避，不无限反复启动。

存在机械手反馈、SDK 手套会话、官方 Viewer、标定、诊断或尚未确认结束的会话时，目录会说明扫描为何不可用。已有会话应在所属工作区明确结束，不会为刷新目录而被自动断开。

## 怎样理解目录状态

| 显示内容 | 含义 |
| --- | --- |
| 已发现 | 最近一次发现收到了这个身份，不等于已经连接 |
| 左右待确认 / 身份提示 | 缺少设备报告的左右手，或信息仅来自编号规则 |
| 使用中 | 工作台掌握了对应设备会话的占用信息，不等于电机已启用 |
| 已过期 / 暂不可用 | 结果缺少有效时间、已超时、发现失败或身份无法一致核对 |
| CLI 运行中 | 官方程序已经启动，不代表它持续报告了反馈新鲜度 |

同一编号的多个传输地址会合并。明确的类型、代际或左右手报告互相冲突时，该身份不能作为可用设备选择。编号规则提供的提示不会成为已经核实的连接身份。

已打开的其他工作区也会提供只读身份与占用观察，不会为读取目录新建工作区或连接设备。通过手套会话配对的机械手须有匹配的 SDK 身份才加入目录；子工作区断开后保留的旧编号不能作为仍在占用的证据。各来源保留各自的观察时间，不能拿新 SDK 反馈延长旧官方扫描的有效期。

发现结果有约 30 秒的有效期。重新扫描开始后清空本次官方扫描的可选结果；失败时保留错误，不复用旧结果来启动 Viewer。已连接 SDK 会话的实测状态与这次扫描分开呈现。

## 选中的设备不会被悄悄替换

官方画面、手套预览和标定选择会同步所选手套编号。手动更换后，刷新和切换语言仍保留这个选择；目标不再出现在有效结果中时，要求重新发现或选择。

机械手连接会重新核对指定编号。其他设备先出现在 SDK 结果中时，会在有限发现窗口内继续等待指定设备；到期仍未发现就报错，不改连第一只设备。连接后仍须核对实际序列号、代际和左右手。

SDK 预览需要 Linux 控制端自己的设备连接及命名用户配置。点击“设置手套预览”先准备这些控件；确认用户后，再点击“连接手套并预览”。发现目录并不代替 SDK 实际连接检查。SDK 预览与原版 Viewer 不同时占用同一设备。

## 标定怎样使用这份目录

标定页读取共享设备缓存，刷新用户档案不再额外启动一轮设备扫描。用户档案查询与设备目录分别显示错误；查询暂被会话占用阻止时，历史用户标为未核对，不能拿旧状态开始标定。

开始标定属于明确操作，会再次发现并核对所选手套。Windows 默认配置下仍由原有 Linux 用户环境执行官方标定，通过实际地址连接，并核对设备类型、完整编号和左右手。未选命名用户、已有模型需要确认覆盖或身份不一致时，保留官方流程要求。收到图像或原始数据不等于完成标定。

## 组件与验证范围

本版沿用同一软件身份与用户数据目录，保留已有参数、映射、标定档案及记录。官方 CLI、SDK 的来源和版本管理方式不因统一目录而改变；不安装或升级已停用的 Studio。

Windows 默认主机发现仍使用独立固定的官方 Windows CLI 2026.10.12；Linux 标定及 SDK 映射保留原环境。详情见 [Windows 手套连接说明](Windows-glove-network.md)。0.2.25 的自动发现行为以本页为准，旧版“首次明确点击查找”的描述属于当时入口。

本轮改动使用隔离假接口和合成数据验证。真实手套的完整发现、显示、标定和映射仍需设备接入验收，见 [0.2.25 验证记录](VALIDATION_0.2.25.md)。
