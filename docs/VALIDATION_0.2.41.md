# 0.2.41：Windows 正常启动与设备发现

## 实际故障与证据边界

用户在资源管理器打开 0.2.40 后，首页发现设备提示配置 Linux。真实运行进程返回空 SSH 设置，原有配置却未被覆盖。复测同一程序：工具启动读取原配置，Explorer 启动读取另一套数据。独立只读脚本确认，Codex 的 MSIX AppData 重定向使工具看到包内 LocalCache 文件，正常桌面进程看到标准用户目录；可显示相同路径字符串，但不是同一个文件。

0.2.40 的原配置哈希、源码与安装包核对仍保留；此前安装验收只能证明当时工具启动环境中的结果，不能证明正常双击启动也读取了那些数据。旧测试数量不能替代本次入口复测。

## 产品改动

- 全新 Windows 配置默认使用已有内置控制方式，官方本机发现不再落入空 SSH；此选择不会安装、启用或启动 WSL。已有 SSH、自定义 CLI 和无 mode 的旧 SSH 配置保持原值，不自动改道。
- 同一发现错误只显示一次；原错误与重试入口保留，空列表不再复制整段技术错误。
- 扫描只发现身份。选择设备不自动连接，标定、预览和实机跟随仍须各自明确开始。

## 本机数据恢复与验收

恢复属于这台机器的部署修复，不是软件自动扫描或导入其他应用数据的功能。两套目录先按真实路径、文件身份与摘要清点；仅恢复准确确认的持久资料。原目录保留，目标已有不同内容先备份，不搬会话锁、租约、未确认状态、运行进程、虚拟磁盘或浏览器缓存。原标定库与控制环境的存在、位置和内容须分别核对，不从同名用户推断标定已成功。

最终验收必须从 Explorer 的正常用户环境启动安装程序与工作台，并通过实际服务核对连接方式、内置环境状态、发现结果、手动选择和无自动连接。失败重试另有隔离服务/UI 回归。构建、安装、配置恢复和实际发现结果保存在外部 `outputs/customer-flow-0241`；只以最终记录为已完成证据。

本轮不执行佩戴采集、实机跟随、固件刷写、WSL 安装/重置或模型训练。实际设备不存在时不伪造发现/选择成功；物理标定质量、跟随效果与时延仍需相应实物验收。
