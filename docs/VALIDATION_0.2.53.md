# 0.2.53 主动复查与完整过程恢复

上一轮对修改点的验证没有覆盖所有相同写法和组合操作。本轮继续检查正常、重复、失败、恢复及不同请求顺序；修复后由非作者使用不同故障位置交叉复查。今后各项修改按[验收规则](QA_WORKFLOW.md)执行。

| 流程 | 已复现的问题 | 修复与复查 |
| --- | --- | --- |
| 任务启动 | 线程构造或启动失败后，更新、组件、诊断、配对、编组、工作区及标定接续保留假忙碌 | 只撤回本次尚未派发的意图，恢复可重试状态；不停止已有SDK或参与者，不清外来占用 |
| 启动调度 | CLI首次检查已完成，但调度任务启动失败后重试又发起首次检查 | 独立记录首次检查已发起，调度重试不依赖检查线程是否仍存活；此问题由独立复查补出并再次修复 |
| 主反馈与参数同步 | 启动失败留下connecting或syncing，阻止后续操作 | 只删除本次未启动的反馈记录和代次，保留旧设备未知停用事实；参数不变，显式重试可以完成 |
| 手套与编组预览 | 未启动的reader仍显示连接中；编组watch未启动但本地预览已暂停且占用仍活跃 | 标明本地reader和transport没有启动，不伪造SDK退出确认；本地预览仅按准确run_id停止，硬件准备不发送控制指令，无法确认时继续保护 |
| Studio组件 | 后台操作或打开任务启动失败后保留忙碌和共享占用；旧实例停止可能误清同进程替换后的新会话 | 只释放本次原token；释放失败保留cleanup_required；停止前后反复核对准确归属，外来标记和新活跃实例不受影响 |
| 诊断结果 | 旧轮询覆盖新诊断，误显示已结束并开放按钮 | 请求和服务代次失效旧回复，失败/离线后由新鲜状态恢复；按钮重复点击不重复派发 |
| 节目单与设备更新 | 离线后仍能发起节目；离线前维护回复晚到，重新开放升级入口 | 离线阻止新操作，旧成功和失败回复均不得跨服务代次回写；晚到节目lease只绑定新鲜状态确认的准确运行 |
| 诊断文件 | 第二次写入部分失败会破坏上次有效报告；读线程启动失败可能漏进程收尾 | 使用临时文件、flush/fsync及原子替换，保原报告和本次内存输出；读线程与未启动流分别收尾 |
| 支持包 | SSH/WSL收取中断留下残缺附件；本机生成无效ZIP也丢失已取得输出 | 所有模式临时收取或生成并验证ZIP再发布，失败保留stdout/stderr及本地简报，不提供残缺官方附件 |
| 录制收尾 | 摘要写入失败不可重试，终结异常可能跳过设备清理；raw刷新失败会被后续摘要成功掩盖 | 冻结待保存摘要，阻止新录制覆盖，只由显式停止重试，保持原始文件及完整性未知事实；一、二代清理均不中断，页面提供重试保存并持续显示未知完整性 |
| 报告接收与导出 | 报告保存失败会跳出接收循环，丢失本次报告及后续关闭确认 | 原子保存；失败继续接收，保有界本次原始JSON与未落盘提示，准确ID只读导出；缓存逐出后撤销可用标记，未知硬件停用事实保持 |
