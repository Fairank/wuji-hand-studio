# Windows 0.2.6 窗口拖动与折射验证

## 改动

此前每次窗口坐标或尺寸变化都会结束并重建 Windows Graphics Capture 会话。0.2.6 在同一显示器内保留原会话，持续更新四边裁切坐标；仅跨显示器或显示模式变化时重建。运动时加快位置检查，网页不再重复写未改变的画布位置。未改变折射的手动开关、默认关闭或机械手控制。

## 已验证

- 382 项 Python 测试通过，1 项跳过；包含新增的同屏移动/缩放保持单一会话、移动后实际取样变化、跨屏创建第二会话。
- 折射节奏的 JavaScript 检查及语法检查通过。合成浏览器中，45 毫秒卡顿和 30 Hz 画面后开关仍选中、画布仍存在，控制台无错误。
- Windows 可执行文件构建及内置自检通过；0.2.6 安装器编译完成。通过工作台自身升级接口安装后，应用显示版本 0.2.6、窗口就绪、机械手与手套断开。
- 安装包 SHA-256：`afa716a087760337b5a9f3012cf041f32f60a705a1103a46f26f65f3b59148fb`。

用户在安装版实际开启并试用折射后的维护快照：所在显示器 165 Hz、采集请求目标 120 Hz、网页呈现约 54 Hz、边缘 JPEG 编码平均 3.77 ms、网页处理平均 6.6 ms、显示间隔最大 31 ms；同屏移动期间 `capture_sessions_started=1`、`geometry_updates=298`。这些计数支持“未在每次移动时重启捕获”的结论，同时清楚表明真实显示流畅度仍未达标。采集当时已由用户关闭，故没有保留可解释的实时采集 Hz 值，不能把网页 54 Hz 全归因于某一环节。

## 尚未验收

用户现场试用显示呈现约 54 Hz，不能宣称已达到 60/120 Hz 或苹果 Liquid Glass 的视觉和动态效果；自动化像素测试仍全是合成图案。当前四张 JPEG 通过 WebView 桥接和解码；Windows 原生 Acrylic 由系统合成器完成，路径更轻。下一版应量出桥接、解码、上传各段时长，并优先验证无 JPEG/base64 的原生共享缓冲区或 GPU 纹理链路，而不是只提高采集目标 Hz。用户开启折射期间才读取外部画面，维护截图继续遮盖外部纹理。
