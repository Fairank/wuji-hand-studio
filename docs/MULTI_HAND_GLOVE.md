# 多手、手套与标定 / Multiple hands, gloves and calibration

这是非官方的 Hand Workbench 功能说明。工作台使用官方 SDK/CLI，界面并非 Wuji Studio；软件测试与实机验收分开记录。

## 一台 Windows 软件里的多个工作区

在「多手设备」发现设备，选择加入已有工作区或新建工作区；也可先建空工作区，再添加设备。一个工作区可包含多只手，整个软件包含主会话最多八只。每只手拥有独立设备会话、参数、节目单、映射与日志；「单手设置」打开对应页面，顶部「多手」回到总览。空闲时可把手移动到另一个工作区。

「停止全部手」请求停止全部会话与群组；错误会明确显示，发送请求不等于确认停用。相同动作及左右连贯编排见 [多手编排说明](MULTI_HAND_GROUPS.md)。

同侧有多只手时按实际扫描的序列号选择，不取扫描列表里的第一只。同一设备在同一 Linux 用户下由一个工作台控制进程占用。工作区保存数据和端口，退出重开尽量恢复原来的本地页面地址；端口被占用时会换用空闲端口。

## 手套到机械手

在「连接与校准 → 实时可视化」扫描手套，选择手套、SDK 用户及配对机械手，再连接预览。先检查骨架和映射姿态，再连接机械手只读反馈；确认现场后手动开始跟随。扫描、预览、创建工作区和保存映射均不启用电机。

链路是：官方 21 点骨架 → 官方 RetargetSession → 工作台 20 关节幅度/偏移/平滑 → 既有控制器 → 实测反馈。表格分别显示原始 SDK 角度、映射目标、发送目标和实际角度；没有反馈时不把目标当成实际姿态。

二代手使用官方关节发布接口；一代手的手套跟随使用官方 LowPass 接口。一代接口没有二代 MIT 参数、电流反馈或同样的关节诊断，不伪造这些值。左右手和代际在连接时核对，不通过画面镜像代替映射。

Windows 完整遥操作使用工作台管理的 Linux 控制端，也可选择外部 Linux。内置 Linux 的以太网发现与 Windows 原生界面集成；一代 USB 设备仍需让 Linux 实际获得 USB 设备访问权，不能把“有一代模型”理解成已经实现任意 USB 自动透传。物理网络、具体固件、手套及多手组合仍需实物验收。

## 与官方流程一致的手部模型标定

「连接与校准 → 手套校准」使用官方 `wuji --jsonl calib hand-model`。先创建或切换命名 SDK 用户；Default 不保存标定。选择捕获手套和左/右侧，已有模型时明确选择是否覆盖。

六个参考姿势依次是拇指与食指、中指、无名指、小指的指尖相碰，四指弯曲约 90°，四指伸直并拢。采集、稳定性判断、约束判断和求解由官方 CLI 执行。页面保留官方结构化诊断；未识别的字段展示原始信息，不猜进度、索引、成功条件或阈值。只有收到官方成功结果且进程成功退出才显示完成。

标定按命名用户和左右侧保存；同一用户同侧换手套不必新建人体模型。这与下方“设备配对的输出映射参数”是两套不同的数据。

取消命令传给 Linux 内实际运行的官方 CLI；关闭软件先等待其释放设备。标定与 SDK 用户修改会检查其他工作区的占用。工作台保存本次 CLI 事件与结束报告到自己的 `calibration_reports`，这不是官方 Studio 那种全传感器 Calibration Debug 录制。

官方说明：[Studio 标定流程](https://docs.wuji.tech/docs/en/wuji-studio/latest/calibration/)、[CLI 标定接口](https://docs.wuji.tech/docs/en/wuji-cli/latest/hand-model-calibration/)、[官方遥操作例程](https://github.com/wuji-technology/wuji-sdk/blob/main/examples/python/retargeting/1.teleop_real.py)。

## 输出映射与预设

在「手套 → 手映射」调整每个关节的幅度系数、角度偏移与整体平滑。默认系数 1、偏移 0、平滑 0，保留 SDK 输出。配置按代际、左右侧、手套序列号、SDK 用户与配对机械手分别保存，可建立命名预设供手动复用；换设备不会自动照搬另一设备的调整值。

保存不会改变运行中的实机目标。没有连接机械手时，可把保存值应用到手套预览；已有机械手反馈或正在跟随时，重新连接以载入。页面对比“保存值”和“控制端正在使用的值”，发出应用请求不等于控制端已经接受。

这些是 SDK 求解后的输出调整，不是重新训练，也不修改官方求解器内部参数。调整不代表实机验证，超过对应模型关节范围的目标仍不能作为有效关节指令发送。

## 验证边界

发布前分别运行参数保存/隔离、输入校验、失败恢复、多会话占用、取消标定、模拟手套失联、界面交互与安装包自检。实物验收仍应检查具体型号的连接、标定、左右手映射、两套设备并行及停用反馈；模拟测试通过不记录为实机通过。
