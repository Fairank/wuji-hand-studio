# 0.2.48 软件流程检查范围

本轮在独立源码和隔离数据目录修复、复查。用户要求仅通过代码操作，先完成软件检查，设备稍后接入，并由用户自行在软件中更新。没有替用户安装工作台、升级现用CLI、刷写固件或驱动灵巧手。

## 修复内容

0.2.45下载0.2.47的真实故障为：260543489字节安装包收到171048960字节时触发180秒总时限；旧0.2.45完成记录与新失败同时显示，超时又被显示成网络无法连接。新版本扩大完整下载预算、分开检查/下载/安装错误与取消状态，保留实际已收字节，禁止以旧完成记录表示本次更新成功。

准备好的安装包还须与当前仓库、版本、文件名、地址、长度和SHA-256全部相符。同版本资产改变时，明确撤下旧包并重新准备；不覆盖未知文件。官方API限流时仅允许同仓库最新稳定标签与可信资产地址的备用目录解析，下载仍必须核验长度和摘要。

旧版客户端自身的180秒限制不会因发布新源码自动消失。因此Windows构建新增小型联网入口，随后使用原版Inno下载页获取固定版本的完整离线安装包，显示实际进度，检查长度和SHA-256，等待原安装器退出并传递结果。完整离线安装包仍可独立使用，安装身份与用户资料目录不变。构建、公开发布和用户实际安装分别留证，不能互相代替。

预览每次运行有独立身份；暂停、继续与停止不作用于后来开始的新动作。节目单控制等待权威状态，停止可覆盖未完成的暂停请求。录制请求未确认时锁定标签与时长。目录读取失败后可明确重试，并恢复主动作选择器。模型状态读取失败保留最后确认结果；迟到的旧请求不能盖过新成功结果或清空未保存的连接设置。

多手工作区写盘失败不会留下假条目，移动和移除须先确认目录保存。只清理本次创建的附加会话，主会话和其他设备保持准确归属；退出、进程结束或目录替换失败时不假报移除。连接请求回执丢失且清理未知时，保留现有卡片与序列号约束，旧断开或错误快照不能诱发重复创建。初始镜头回执失败单独提示，不把已完成的添加当作失败。
