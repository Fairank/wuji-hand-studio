# 0.2.66 连接故障与新顺序验收

本轮用户截图显示已选择右手映射，却报 `Unknown hand generation/side`。只读读取本机软件既有状态确认：当前目标为 Hand 2 右手，新的官方发现记录只含编号、设备类型、UDP 地址，没有左右手字段；库存归一侧别为未知。原代码把该空值拼进型号。匿名化后按相同字段形状用实际 Handler、Controller、Bridge 和 SDK 工作线程回放，先复现原错误，再修复。

未知物理侧别时，沿用显式选择或当前映射型号作为目标意图，不标记物理侧别已验证。使用原有 SDK 连接与身份检查：真实侧别匹配才订阅数据；SDK 报告左手或未知而目标为右手时关闭准确候选，零订阅、零跟随；明确改选左手并使用对应标定后可成功。已归一的左右手冲突仍在释放前拒绝。未知原始元数据保留既有归一兼容，没有新增设备协议或连接层。

新增九组确定性阶段测试用事件屏障交错目标预核对、原会话退出、模型读回、连接派发和完成回执。原取消缺口为：模型核对完成后、接入指令尚未发出，取消已确认，但旧回调仍会发出一次接入再清理。现在最后派发使用现有用途任务锁，和准确取消串行；检查只读本地任务、取消及截止时间，不再次读取档案或申请 Controller 锁。已经开始派发时，取消可能等待该派发结束，并通过原确认机制清理。

同服务双标签另外复现了旧请求晚回复覆盖新会话用途的提示错误。错误现在归属原任务；退休提示须有不同于失败任务、也不同于派发前旧任务的后续成功回执，并与实际设备、人员和 SDK 会话匹配。当前失败、坏回执、普通跟随停止造成的状态变化仍保留错误。双标签整页流程包含两设备、离线卡、取消、快速重复点击、同侧配对、模拟跟随、另一虚拟页停止、断开后清除已应用状态和明确重试。

独立复查包含资源检查与连接交错、元数据失败、报告保存失败与原件读取、停止清理失败的恢复，以及 Controller 快照、最终派发和取消并行的锁顺序。各次原始失败、夹具错误、修复后证据和准确源摘要在仓库外分别保留。真实设备状态读取仅为软件现有记录，没有为验收连接、重连、刷写或启动实机动作。

测试使用隔离 SDK、设备、进程及网络端点和完整源页面，代码 Playwright/无头 Edge 仅访问回环服务。最终回归、打包、本机更新后的运行内容和资料保留、Git 同步另记交付清单。合成控制和真实字段形状回放不等于真实 USB/网络时序、断联率、温度或动作质量验收。
