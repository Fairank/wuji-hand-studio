# 独立官方 CLI 与原版 Viewer

本文说明同一个非官方个人工作台中的实现行为。Windows 0.2.20 的构建、安装记录保留在文末；0.2.21 新增本地原版空 Viewer，其已完成验证和待验收范围见 [0.2.21 验证记录](VALIDATION_0.2.21.md)。

**0.2.23 Windows 路径变更：** Windows 内置 WSL 的默认设备发现与实时 Viewer 改用独立固定版本的主机原生 CLI；Linux 标定及用户档案仍保留。下文的 Linux runner 与自动更新说明不代表原生 pin 会同步升级。当前使用方式见 [Windows 手套连接与官方画面](Windows-glove-network.md)。

## CLI 与 SDK 分开维护

工作台从固定的官方仓库 [wuji-technology/wuji-cli](https://github.com/wuji-technology/wuji-cli) 检查 CLI 发布版本。CLI 独立更新不会同时升级内置 SDK、替换整个控制环境或迁移用户的校准档案。

`git clone --no-checkout` 和所选 tag 的 `git fetch` 用于保留官方仓库及记录对应 commit。这个源码镜像不是 CLI 二进制的构建结果；可执行文件来自该版本实际列出的官方 Linux x86_64 release 归档。

设置中的“官方 CLI / SDK”保留配套组件检查，同时提供独立的 CLI“检查更新”“更新 CLI”和“回退上一版”。远程 SSH 配置及用户明确指定的自定义 CLI 路径不会被独立版本路径覆盖。

## 启动检查、准备与切换

主工作台每次启动会发起一次后台更新检查；同一进程不会因重复初始化反复启动检查。子设备工作区不各自重复检查。开发环境可用 `WUJI_CLI_AUTO_CHECK=0` 禁用启动检查。

发布发现优先读取匿名 GitHub release API。遇到 403、429 或超时，回退到同一官方仓库的真实 `releases/latest` 重定向或选中版本页面，再解析 `releases/expanded_assets/<tag>` 中实际存在的下载链接。

网页回退只从同一个资源行读取与文件名精确对应的 SHA-256；冲突、错行或缺失摘要都会拒绝更新。已用真实 API 403 和官方发布页验证该路径。网络连接等待与整个传输时限分开：受管理 CLI 下载允许最多五分钟，单次网络等待最多二十秒。关闭软件会请求取消，取消后清理本次暂存并保留旧版；先处理设备停止与断开，再等待软件任务退出。

| 阶段 | 实际依据 | 尚不能表示的结果 |
| --- | --- | --- |
| 发现版本 | 官方 release 元数据或页面中的 tag、资产链接 | 归档已下载或校验通过 |
| 准备版本 | 下载归档、核对 SHA-256、安全解压、记录来源 commit | CLI 已执行、兼容或被选用 |
| 软件检查 | 新 CLI 的版本及所需帮助接口实际返回成功 | 设备已连接、反馈在线或标定成功 |
| 切换版本 | 全工作台闲置检查通过，原子更新版本选择记录 | SDK 同步升级或实机验收完成 |

SHA-256 必须来自官方资产元数据的 `sha256` digest，或该 release 实际列出的校验文件，并与选中归档精确对应。仅有网页 tag、源码 commit 或下载地址不能代替二进制摘要。发现了版本但拿不到有效摘要时，准备会报错，不会把它标成可用版本。

每个版本有独立目录，包含归档、解压内容、`manifest.json` 和 `metadata/source` 中的 git 仓库。清单记录版本、tag、commit、归档摘要、文件摘要及路径。下载与准备失败不会覆盖已选用版本；未完成的暂存内容不会成为正式版本目录。

后台准备完成后，还需核对 CLI 版本，以及 `--help`、`viz --help`、`calib hand-model --help` 中工作台依赖的接口。这些是软件检查，不会执行设备标定或机械手动作。

切换等待主工作台和其他设备工作区均能确认闲置。活动设备连接、参数同步、标定、官方可视化、未确认的设备停止等状态会阻止交接；不会为升级强行结束设备会话。CLI 版本选择和可视化会话共用交接锁与会话标记。

## 保留旧版与回退

成功切换会在同一个原子选择记录中保存当前版本和上一版。旧版文件保留，准备失败、软件检查失败或指针替换失败时，原选择记录保持有效。

“回退上一版”同样要求闲置，并在交接锁内读取当时的上一版，再原子交换选择。主动回退会记住被回退的版本，避免下次启动立即自动装回同一版；更高的新发布版本仍可进入正常检查流程。

主动点击“更新 CLI”可以重新采用刚回退的版本；启动自动检查不会替用户撤销回退选择。

独立版本只接管受管理的默认 CLI 路径。自定义路径或 SSH 控制端继续使用原配置；没有通过独立版本验证的记录不能任意指定外部可执行文件。

## 不接设备打开空窗口

进入“连接与校准 → 官方可视化”的“直接打开”，可打开完整原版 Rerun 0.36.0 空 Viewer。此入口不运行 `wuji viz`，不扫描、连接设备或加载 SDK；没有模拟骨架、传感器数据或实测反馈。需要设备实时画面时，再切换“设备画面”。

Viewer 使用固定官方 CDN 的 HTML、JS、WASM、图标和许可文件，随本地资源提供。仅从 HTML 壳移除外网 Google Fonts 标签，JS 与 WASM 不修改。HTML、JS 与所用 CLI 的内嵌资源字节一致；CDN WASM 不与 CLI 内嵌版本字节一致，不能称为从 CLI 完整提取。来源、大小和 SHA-256 固定在 `src/official_viewer_manifest.json`，`prepare_official_viewer.py` 准备和校验资源，构建前再次校验。

空 Viewer 由独立回环地址和临时端口提供，只允许静态资源，不提供工作台 API。HTML 响应以 `Clear-Site-Data: "storage"` 清除此独立地址的存储；不依赖该版本实际忽略的 `persist=0`，也不清理工作台设置。隐藏欢迎示例，不传入记录或数据流地址，CSP 限制联网请求。

已在真实 Edge 中启动原版 WASM 和空 canvas，重载后存储哨兵删除，实际外部请求和页面异常均为零。原版遥测请求被 CSP 拦截，控制台仍保留对应提示，不能把“零页面异常”写成“零控制台错误”。0.2.21 的安装版 WebView2、完整界面、构建与发布验收仍待最终记录。

## 设备实时画面

入口位于“连接与校准”中的“官方可视化”。先查找并选择官方设备列表中实际返回的序列号，再由用户明确打开。当前启动入口支持 Windows 内置 Linux 或本机 Linux；远程 SSH Viewer 的独立隧道接入尚未实现。设备范围为 Hand 2 和 Glove，Hand 1 会被拒绝。

工作台通过 Linux runner 启动所选 CLI：

```text
wuji viz --sn <选中的序列号> --no-zero --no-open --jsonl
```

工作台不为可视化追加电机使能或运动动作。`--no-zero` 表示跳过官方触觉清零步骤；官方 Glove 可视化仍会应用 `stream-config` 数据流设置，不能把它解释成设备完全零写入，也不能据此宣称校准已完成。

runner 保持当前 SDK 用户选择并持有用户档案与设备会话的互斥。在退出确认前，不把同一设备交回工作台控制路径。原始 CLI 标准输出保持原样；工作台自己的进程事件另用 `workbench_event` 标识。

显示采用一个原版 Viewer iframe，不复制其骨架、触觉或关节面板。后端分别验证 Viewer HTTP 地址和其 `url` 参数中的 Rerun 数据端点，均须为允许的本机回环地址，并检查两个端口可连接。切换明暗主题只替换 `theme` 参数，保留原数据端点和其他查询参数。

“CLI 运行中”、启动记录、端口可连接以及 iframe 页面载入，只表示启动或显示阶段得到相应确认。官方启动记录没有提供持续数据新鲜度，状态因此保留 `stream_freshness=not_reported`；保留的画面不能当作当前设备反馈在线的证明。

重新载入画面、切换页面或退出专注查看只影响显示。需要结束设备会话时，使用“停止可视化”。

## 停止与未确认退出

runner 只停止自己持有的子进程，并在子进程退出、设备和用户档案互斥均释放之后，返回带所选序列号的明确清理确认。工作台不会仅因 Windows 启动器消失或进程返回非零值就清除可视化会话标记。

停止超时、启动器异常退出或清理尚未确认时，保留会话标记并阻止新的设备控制。后续“停止可视化”可调用独立的 runner 恢复检查；不能清除其他扫描或版本切换操作的标记。关闭工作台时也会处理仍保留的可视化会话。
