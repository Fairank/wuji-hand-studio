# 更新记录 / Changelog

## 0.2.72

- 按用户要求移除遥操作渲染链的自研防穿模投影，直接显示当前官方 SDK 目标，保留已有用户映射设置；不再创建或推进自研碰撞实例。
- 目标帧身份与原数据期限同时传至主画面和独立小窗，错误设备、人员、型号或迟到旧帧不显示；保留原实机反馈和动作展示路径。
- 保留刷新等待及解码超时修复，原样式、图标、导航和功能入口不改；显示流程仅使用模拟信号验收，不运行真实 SDK、设备或物理仿真。
- 官方公开接口未找到可调用防穿模合同，不声称闭源内部绝无碰撞处理或保证不穿模。验证范围见 [0.2.72记录](VALIDATION_0.2.72.md)。

## 0.2.71

- 本地 HTTP 服务的待接入队列扩大，避免启动资源并发时默认小队列丢失连接；保留原协议、线程模型与访问限制。原界面资源及功能入口不改，安装后的样式和入口缺失会阻止交付。
- 主画面与独立小窗按请求起点计算刷新周期，取消取图、解码完成后的重复等待；解码超时释放轮询，旧解码结果不能覆盖新画面。
- 映射图像使用原源数据期限，覆盖最终状态校验等待、发布锁、缓存、网络与浏览器解码；新的 SDK 帧不延长旧图像的期限。
- 同一不可变模型与准确姿态的完整几何证明可复用，避免重复检查占满预算而使新姿态持续不前；新候选与路径仍按原覆盖、间距和预算检查。
- 不改 SDK 输出、用户滤波设置、设备控制或连接流程。验证范围与实物限制见 [0.2.71记录](VALIDATION_0.2.71.md)。

## 0.2.70

- 修复设备目录丢弃已确认但数据暂时过期的会话行后，又补成未知左右手的问题；准确 SDK 与官方查看会话的身份信息保持，数据新鲜度不伪造。
- 官方未接入发现本来不含手套侧别时，明确说明连接后识别，不根据序列号或历史猜。短暂空发现的待复核记录保持原发现时间和原时限，不授予新接入权限。
- 数据停止更新时，用户明确重试同一 SDK 用途会沿原确认退出与准确重接流程执行；新鲜会话仍复用。已存人员资料、模型和准确原路由在预核对成功后转交，不自动重连。
- 纯界面刷新允许准确的只读手套预览继续接收，保留会话；配对、跟随、退出不明及其它繁忙状态仍拒绝。关闭软件和安装更新的原空闲要求不变。
- 验证范围与实物限制见 [0.2.70记录](VALIDATION_0.2.70.md)。

## 0.2.69

- 标定运行或结束待确认时保留准确设备会话卡，可返回原任务；不会把占用卡伪装成实时发现或允许重复连接。
- 官方画面的标签、设备选择和标定提交共用同一侧别投影。旧扫描记录缺少侧别时，采用同一设备当前已确认 SDK 身份；已有相反报告仍明确阻止开始，不根据历史或映射选择猜测。
- 移除 MuJoCo 显示每帧固定角度追赶限制；原碰撞路径证明、限位、查询预算和过期保护继续生效，不改变 SDK 目标或真实手指令。
- 标定超时显示当前动作、官方错误、最后指标与阈值，不再直接显示错误字典或只要求保持平稳；不修改官方采集条件或自动重试。
- SDK 兼容预检补齐模型路径设置、读回、异常类型及导出等已有依赖接口，避免安装后才发现接口缺失。验证范围见 [0.2.69记录](VALIDATION_0.2.69.md)。

## 0.2.68

- 已验证的人员标定接入，在自定义人手模型路径确实未设置时，调用官方 SDK 设置准确已存模型路径，再读回并核对模型内容后订阅。错误身份、不同自定义模型、设置失败和错误读回继续拒绝，不覆盖其它标定。
- SDK 模型参数未设置不再被界面泛匹配为“未标定”；只对明确不存在已存标定的情况提供标定入口。
- 遥操作页增加复用统一用途切换的选择、开始和重新接入按钮，保留当前模式。虚拟预览不启动实机，实机仍需明确配对并单独启动跟随。
- 永久回归、真实源码隔离链及未执行范围见 [0.2.68记录](VALIDATION_0.2.68.md)。

## 0.2.67

- 在设备页连接手套或灵巧手后留在当前页面，由用户明确选择查看、标定或遥操作；连接回复晚到时不拉走用户已切换的页面。
- 已存标定接入使用原 45 秒用途切换总预算，SDK 启动、导入和资料读回不再被局部 12 秒等待过早截断。普通未标定、官方画面和灵巧手反馈连接仍沿用原等待预算。
- 新 SDK 会话失败后的清理诊断绑定准确任务与会话。完整 ACK、读取线程退出、传输关闭和停用证明确认后解除历史阻塞，允许重新扫描和明确重试；原失败原因保留，缺失或不匹配证明不放行。
- 复现、取消、总预算耗尽、延迟退出确认及明确重试范围见 [0.2.67记录](VALIDATION_0.2.67.md)。

## 0.2.66

- 修复真实官方发现只返回设备编号、类型和 UDP 地址，没有左右手字段时，所选右手映射仍触发 `Unknown hand generation/side` 的问题。未知物理侧别使用当前映射目标意图，SDK 连接后必须核对真实侧别；冲突或 SDK 未能报告侧别时关闭候选，不订阅或跟随。
- 最后接入指令与准确取消复用同一用途任务锁：取消已先确认且指令尚未派发时不再开手套；已经派发的连接仍按准确会话清理，不承诺撤回已发生的外部操作。
- 页面错误绑定原任务与原归属，只有经过核对的后续新切换才能退休旧提示；普通跟随、停止或已有旧回执不会清除当前真实错误。
- 同形真实字段回放、九组确定性交错、资源协调及双标签复查见 [0.2.66记录](VALIDATION_0.2.66.md)。

## 0.2.9 — 多手工作区与双手连续动作

这次把“每只手只能单独开工作区”扩展成“一个工作区可以管理多只手”。发现设备后，可以加入当前工作区，也可以新建工作区；原有单手连接、参数、手套配对及标定继续独立保存。

### 新增

- 右上角多手入口；新建空工作区、发现设备后分配、空闲设备移动及离线模型预览。
- 同一工作区内 2–8 只手执行同一个手指舞，或一左一右执行连贯编排。
- 八组双手动作：跨手波浪、反向波浪、往返波浪、中心向外涟漪、双手交替、同步绽放、十指钢琴、双波追逐。
- 各只手独立的原生 MuJoCo 画面、正面视角与拖动调视角，明确标出预览、实测反馈或参考姿态。
- 速度、幅度及循环设置；共同开始时间，并按最慢参与手调整各段时长。
- 全组停止与停止全部手，展示设备级错误和未确认的停止。

### 修复与整理

- 同一只设备连接尚未完成时，重复添加会被识别，避免创建重复会话。
- 一只手准备失败时清理整组；控制连接超时会结束整组；启动过程中点击停止也会继续处理。
- 多手页面刷新和中英文切换保留当前选择；修正代次显示、指令字段和成员状态。
- 修复新双手画面的裁切与重复标题，保留黑白主题和原生磨砂，没有恢复桌面折射。

### 已验证与尚未验证

Windows 463 项通过、2 项跳过；Linux 33 项通过。两个独立预览进程及打包程序通过完整播放、手动停止、控制超时与设备移动检查。已原位安装并检查原生窗口，保留用户数据。详细证据见 [0.2.9 验证记录](VALIDATION_0.2.9.md)。

本轮没有驱动真实机械手。真实多手编排目前需要二代手共享同一 Linux 时钟域；一代群组动作仅预览。多底座之间的碰撞、实物手套组合和机械同步精度尚未验收。这些动作是自编轨迹，不是官方录制。

本地 Claude Opus 5.5 max 完成五项基础代码、界面、测试和文档任务；主助手设计并审核控制协调与验收。公开软件不含私有训练模型和凭据。
