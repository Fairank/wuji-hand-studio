# 更新记录 / Changelog

## 0.2.19 — 内置官方 CLI / SDK 与恢复修复

本节记录本次源码变化，构建、安装与发布状态需由 [0.2.19 验证记录](VALIDATION_0.2.19.md) 和实际 Release 确认，不表示已经完成整体验收。

- 按用户最终选择取消 Studio 嵌入，移除页面、安装和打开入口。S1–S3 Studio 改造取消，不作为本版新功能；0.2.18 记录保留为历史。
- 「设置 → 连接与设备」新增官方 CLI / SDK 卡片，管理配套 CLI / SDK 2026.10.12、控制环境 1.1.0。环境安装记录、配套目标与实际版本/SDK 导入检查分开显示，实际检查不连接设备或使能电机。
- 后端只保留旧 Studio 状态查询、核对与关闭兼容，拒绝新的安装、更新、选择和打开；不主动删除 Studio HOME、标定或用户档案，不自动合并到 CLI 用户数据。
- U1：子工作区始终显示当前设备名和返回多手总览入口；返回保留子会话，不发送停止或断开命令。
- U3：校准操作错误与刷新错误分离；刷新失败保持官方状态待核对，成功刷新只清读取错误。
- 移除重复的六姿势卡片、插图与姿势选择器。标定只保留一个官方 CLI 入口和紧凑的当前步骤、官方进度、结果与错误；原始事件详情默认折叠，不额外安装一套标定功能。
- U4：隐藏主/子画面暂停图像请求和解码，重新可见恢复；MuJoCo 渲染按显示需求工作，SDK 接收、设备控制和心跳保持独立。桌面菜单与退出确认补充可访问名称。
- 修正 Hand 1 手套实测显示的 0–19 编号，Hand 2 保留对应的各指设备编号。未知代际、陈旧或不完整反馈不回退成可信的目标动画。
- 连接手套时保留所选 SDK 用户直到会话结束，断开对象后再恢复先前用户，避免过早切回而重载其他用户参数。
- 停用未知按设备和会话持久保留；新只读连接、其他设备的停用确认或进程结束不自动清除。退出和升级继续核对未确认状态。
- 中断或哈希不符的安装缓存可重新暂存，完整校验后原子替换；失败不发布半成品，关闭失败或退出超时不启动安装器。
- 构建器核对缓存程序自检中的产品身份与版本，使用独立自检文件，拒绝缺失、无效或旧版本结果。
- 窗口尺寸在同一锁内成对读取并原子保存，避免并发回调保存混合宽高或损坏配置；不改变窗口、DPI 或页面选择。
- 官方标定的错误和取消事件优先于正常退出码，保留真实错误原因，不因退出码为 0 显示完成。
- 提供 Windows 隔离软件检查 CI 模板：语法、模拟升级/缓存/构建失败及选定回归。当前 GitHub 凭据不含 workflow 权限，模板放在 `ci/windows-checks.yml.example`，未启用远端 Actions。模板、局部模拟、安装版和实机验收分别记录。
- 保留一个工作台、原安装身份、用户数据和原生磨砂；不恢复桌面采集或液态折射，不新增无关 Mac/Ubuntu 验收结论。

## 0.2.17 — 官方依赖与故障支持导出

- 顶部、导航、主内容区统一透光，移除盖住系统磨砂的旧白色渐变和额外 CSS 模糊；减轻连接卡片叠加白底。文字与控件保持实色，深色模式同步处理，减少透明度仍恢复实色。
- 修复 Windows 网卡类型字段读取错误造成 USB 以太网被遗漏、同网段配置入口不可用的问题；仅配置用户所选的空闲有线网口。
- 内置 Linux 广播发现不可达时，按官方手套默认数据地址只读探测真实身份，重连再次核对序列号；Doctor 支持填写实际 IPv4:端口。未响应不当作设备故障，不自动跟随机械手。
- 修复 SDK 内置 Default 用户的空标识被连接校验拒绝的问题；明确选择 Default 时不再沿用先前命名用户，设备编号与控制租约仍需有效。
- 连接栏未识别时显示 Wuji Hand，只有 SDK 身份回读与当前编号一致后才显示 Wuji Hand 1/2、左右手与编号。自动发现设置保留在「设置 → 连接与设备」。
- Windows 内置 Linux 镜像 1.1.0，SDK/CLI 固定官方 v2026.10.12；兼容旧环境的离线暂存、切换、验证和失败回滚，保留个人标定和参数。
- Doctor 使用实际 SDK 的 Python 路径，显示官方修复建议；增加可读文本、官方原始 JSON、完整运行记录，重启后恢复上次报告。
- 增加官方 `wuji logs export` 支持包、用户现象、证据边界和故障简报；官方 ZIP 不修改，不自动上传，不清错、使能或运动复测。
- 退出码、警告、失败和跳过分别显示；采集失败时保留部分结果，不把未发现设备标为硬件通过。
- 保持一个 Windows 工作台和原生磨砂。macOS 仅同步准备脚本，尚未验证新的安装包。

## 0.2.16 — 重新组织节目单操作路径

- 编辑区分为动作列表与播放设置，固定底部操作区，长列表不会挤走启动和停止入口。

- 桌面维护接口可只读打开节目单供布局检查；此操作不能发起播放或电机动作。
- 保留原生磨砂和已有有限回弹，未改 SDK、标定、轨迹、控制频率或设备参数。

- 清理隐藏面板占位、非当前页面的装饰残留、重复画面来源按钮和过时的启动提示；改善黑色主题的选中对比与窄窗口布局。原截图白条的确切成因尚未完全复现，验证范围见下方报告。
- 保留真实反馈／预览来源、错误状态、停止入口，以及手套可视化、官方标定、映射。没有调整电机增益、轨迹、发送频率或控制边界。

## 0.2.9 — 多手工作区与双手连续动作

这次把“每只手只能单独开工作区”扩展成“一个工作区可以管理多只手”。发现设备后，可以加入当前工作区，也可以新建工作区；原有单手连接、参数、手套配对及标定继续独立保存。

### 新增

- 右上角多手入口；新建空工作区、发现设备后分配、空闲设备移动及离线模型预览。
- 同一工作区内 2–8 只手执行同一个手指舞，或一左一右执行连贯编排。
- 八组双手动作：跨手波浪、反向波浪、往返波浪、中心向外涟漪、双手交替、同步绽放、十指钢琴、双波追逐。
- 各只手独立的原生 MuJoCo 画面、正面视角与拖动调视角，明确标出预览、实测反馈或参考姿态。
- 速度、幅度及循环设置；共同开始时间，并按最慢参与手调整各段时长。
- 全组停止与停止全部手，展示设备级错误和未确认的停止。

### 修复与整理

- 同一只设备连接尚未完成时，重复添加会被识别，避免创建重复会话。
- 一只手准备失败时清理整组；控制连接超时会结束整组；启动过程中点击停止也会继续处理。
- 多手页面刷新和中英文切换保留当前选择；修正代次显示、指令字段和成员状态。
- 修复新双手画面的裁切与重复标题，保留黑白主题和原生磨砂，没有恢复桌面折射。

### 已验证与尚未验证

Windows 463 项通过、2 项跳过；Linux 33 项通过。两个独立预览进程及打包程序通过完整播放、手动停止、控制超时与设备移动检查。已原位安装并检查原生窗口，保留用户数据。详细证据见 [0.2.9 验证记录](VALIDATION_0.2.9.md)。

本轮没有驱动真实机械手。真实多手编排目前需要二代手共享同一 Linux 时钟域；一代群组动作仅预览。多底座之间的碰撞、实物手套组合和机械同步精度尚未验收。这些动作是自编轨迹，不是官方录制。

本地 Claude Opus 5.5 max 完成五项基础代码、界面、测试和文档任务；主助手设计并审核控制协调与验收。公开软件不含私有训练模型和凭据。
