## 连接和资料如何衔接

设备由同一目录选择；页面按明确用途调用现有 `WujiDeviceUse → WujiConnectionSwitch → ConnectionSwitch`。同用途按实际会话复用，跨用途由后台确认旧资源退出后转接准确设备。官方 CLI 与 SDK 的资源交接可能有短暂数据间隙，不能承诺物理连接绝无中断。

标定结果按官方人员及左右手保存为本机资料，再交给 SDK 导入和核对。界面应区分“已保存”“已套用”“已接入”，不能把保存成功说成已写进手套固件，也不能因路径或身份核对失败就直接要求用户重新标定。

虚拟预览与实机跟随放在同一遥操作页。预览采用官方 SDK 目标；实机须选择准确目标手并由用户明确开始。软件不得因切页、自动发现、标定完成或参数同步而自动启动实机跟随。

## 下一步要做什么

以下是尚待完成的验收和交付条件；“待验收”不等于已经定位或修复了全部实物问题。

### 1. 固件升级完整链路

- 分别列出手套、Hand 1、Hand 2 的官方支持路径，先保留只读检查的具体结果。SDK 能发现设备，不代表官方升级入口已经支持它。
- 核对所选设备类型、硬件版本、当前版本和兼容目录，再进入官方包的下载、完整性核对及明确升级操作。手套已有的 ZIP 与资源读回验证不能冒充两代灵巧手均通过。
- 检查失败必须给出准确原因和可重试入口；兼容目录不存在时不能把当前版本当成“可用新版”，不能继续刷写或自动重复确认。
- 验收标准：检查、进度、失败、中断、明确重试与完成状态一致；完成后对同一设备读回版本确认。没有读回证据不能显示升级成功。未经用户明确发起不做真实刷写。

### 2. 标定、套用及遥操作连续使用

- 覆盖新人员、同人覆盖、左右手分别保存、多人切换、退出软件后重新读取；其他人员及另一侧资料保持。
- 结果须核对准确人员、左右手、模型文件与 SDK 实际导入结果。已有有效模型应能套用，不无故要求重标定。
- 从查看或标定进入虚拟预览时，后台交接原设备，保留所选人员和设置；失败后在同一操作区明确恢复，不让用户猜设备被哪个页面占用。
- 虚拟预览、目标手配对、实机开始与停止分别验收；换目标、取消和旧回复不影响新会话，不自动恢复电机动作。
- 验收标准：先用合成信号走完整条链和异常恢复，再按明确授权另记实物结果。当前完整实物转接与精度仍未验收。

### 3. 接口识别、断联恢复与显示延迟

- 对官方支持的直连网线、USB 转网口、Type-C 扩展坞网口及 USB 设备路径分别建用例；不要求所有设备支持所有接口。
- 检查已有网卡地址、链路、驱动身份、设备实际身份和左右手，不能从序列号或旧历史猜测；没有驱动问题证据，不盲目更新驱动。
- 覆盖插拔、反馈超时、再次发现、明确重新接入和用途切换；失效资源可准确结束，新会话不被旧状态拦住。
- 显示延迟区分采集、SDK 映射、传输和渲染耗时，用同一合成信号对照官方输出与工作台显示，不靠额外滤波或插值掩盖问题。
- 验收标准：只读发现约每 5 秒刷新，不自动连接；身份、状态和可用按钮一致，旧数据不显示为实时在线。长期实物稳定性须有单独持续观察记录。

### 4. 独立手部展示与软件更新

- 展示页应独立选择灵巧手，不依赖遥操作页先选设备；模型预览、实测反馈与实机播放含义清楚，播放、停止、返回和重新进入完整可用。
- 软件、官方 CLI/SDK 组件和设备固件分开显示各自版本与更新状态。研发要求采用官方公开稳定 SDK；每次更新仍需核对兼容关系，不能以扫描为由在使用中切换组件。
- 软件内更新须走完检查、下载、校验、安装、重启、实际版本与资料保留；有明确进度和失败恢复，不用跳转网页冒充完成更新。
- 实时反馈、参数调节、官方诊断和报告导出按入口逐项检查；各导出格式须真正生成并读回核对文件，取消不显示成功，失败后可以明确重试，公开报告不泄露私有资料。
- 验收标准：更新服务器确有可用安装包且完成一次完整软件链；源码上传或能发现新版不作为安装成功证据。本轮没有新增公开安装包。

### 5. 让后续审查真正自动运行

- 保留 `scripts/run_review.py`、PR 核对表、`src/AGENTS.md` 及[完整工作流模板](ci/code-review.yml)。
- 正式工作流已进入生效目录。修改时先用官方 actionlint 核对工作流及模板，再核对该提交实际产生的两轮 Actions 与同源校验，失败则继续修复并重跑。
- Codex 账号自动审查与仓库合并规则另行开启并验证，不能把确定性测试称为 AI 审查，也不能假定账号开关已经开启。

## 后续修改必须遵守

1. 优先官方现成 CLI、SDK、模型和指导，不新增另一套连接管理器或自研标定算法；碰撞功能只采用官方已经提供且能够核对的实现。
2. 未要求改版时，修底层不得顺带改磨砂玻璃、布局、导航和功能入口；必要的功能更改也要核对实际页面。
3. 每项修改复现原失败，检查同类入口，再验证正常、失败、中断、重试、重复操作与旧回复；由非作者独立复核。
4. 发现仅只读刷新；接入、用途切换和实机开始由用户明确操作。退出不明不能当成已释放，不能通过自动重连掩盖。
5. 保留配置、人员、标定和备份，区分源码同步、本机安装、安装包发布及实物验收。只在代码检查完成后宣称软件交付，不承诺零缺陷。
