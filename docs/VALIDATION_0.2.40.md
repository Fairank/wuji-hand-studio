# 0.2.40 修复依据与验证范围

本版继续处理完整使用流程，而非只核对页面能否显示。原 0.2.39 的记录、失败和安装事实保留；新补证据逐任务记录正常终点、取消或停止、失败后的明确恢复和再次使用。源级软件、最终安装包、实际联网读取及实物效果分别验收。

## 已复现的问题与修复

### 安装版版本检查失败的实际原因

实际安装版读取官方 CLI、SDK 发布资料时，在发出网络请求前就出现 `FileNotFoundError`。构建所用 Python 的 `ssl.SSLContext.__new__` 会动态读取同目录 `codex-rejected-cas.pem`，原 PyInstaller 包漏带此文件；这不是用户未联网，也不能只换成“联网重试”文案。

因果诊断只向独立构建目录补入所选解释器的原文件：906 字节，SHA-256 `c916ce1b14ed8ca69e9b5c9fab22799a900dd610d6d4ec9b1347f4fd48e53718`。之后诊断版真实读取到 CLI `v2026.10.12` 与 SDK `2026.10.12`；记录为 `customer-flow-0240/frozen-network-diagnostic-policy-copy-03.json`。这是该次公开元数据读取成功，不是安装或更新成功，也不是以后永远为最新的保证。此前 DNS 失败的诊断记录仍保留。

构建现识别所选解释器是否引用该策略文件，按原字节打包；引用存在而源文件缺失时拒绝构建。打包程序的离线自检必须真正创建默认 TLS 上下文，不能只导入 `ssl`。证书校验和主机名校验保持开启，没有用关闭验证或替换信任规则来绕过缺文件。最终重建包的策略文件、离线 TLS 自检和真实发布资料读取另由最终交付证据核对。

SDK 检查同时保留具体原因：本地文件、缓存、证书验证、普通 TLS、网络、HTTP、元数据格式和未知检查异常分别处理。本地文件问题不再被统一说成断网；普通 SSL 异常不冒称证书错误。有效旧缓存可注明来源继续使用，但失败不会延长其检查时间，过期记录不能显示“已是最新”。文案分类的软件测试与上面的打包根因修复是两件事。

### 遥操作中的实体灵巧手入口

遥操作页直接提供实体灵巧手的查找、准确设备选择和连接。手套已在接收数据时，查找灵巧手沿用原手套、档案与会话，不先断开再准备另一遍；异步失败显示在原任务中，可明确重试。发现只刷新候选，不连接手、不发送电机命令。连接目标读取反馈后，仍须用户单独开始跟随；停止、未确认停用、恢复、断开和再次选择分别保留。

实际 `Controller`、Bridge、worker、任务归属与发现代码有独立检查；页面覆盖来源接收中查找失败/重试、准确 SN 连接失败/重试、明确跟随、停用未知恢复和再次使用。SDK 与设备输入为合成实现，不能据此宣称实物跟随或失联停用已通过。

### 当前发现、原会话与最近连接分开

当前设备只展示新鲜发现。发现超过 30 秒不证明设备已拔线，也不自动停止正常 Viewer：原会话、准确占用和停止入口仍在设备任务中，过程状态不再冒称硬件在线。“最近连接”只记录真实启动事实，不把扫描到设备当成曾连接。

原版启动报告实际可能只有 `sn` 和 `handedness`。历史记录仅在报告 SN 与同次选择的设备 SN 完全相同后，使用明确设备类型补齐；类型缺失、两侧类型矛盾或 SN 不符均拒记，不能凭 `WG`/`WH` 前缀猜设备类别。

整链复验还发现：第一次停止清理失败后，即使下一次明确重试已确认释放，旧错误仍阻止自动发现恢复。现仅在准确原会话的进程、Job 和传输清理确认后清除本次错误；未知或失败分支继续保留占用。测试覆盖发现过期但正常会话不被断开、未知清理期间零扫描、停止失败再重试、自动重新发现后仍由用户选择连接、再断开和再用。没有以发现时间推断真实拔线延迟。

### 设置存储与完整任务缺口

浏览器拒绝读取主题偏好时，旧入口会中断后续脚本初始化，导致设备任务等页面也不能正常工作。主题读取/保存现捕获存储异常并限制合法值。语言、工作台模式、主题、透明与动态效果分别验证拒读、拒写和坏值后的当次操作、恢复保存与重载。当前源码另以两个独立浏览器上下文阻断主题拒读/拒写，确认 HandSessions/TaskWorkspace 启动、深浅主题当次可用及恢复存储后的保存/重载/再用，记录为 `customer-flow-0240/settings/theme-after-final01.json`。

官方画面、手套画面尺寸另作两项任务：各自拒读、拒写和非数值存储值后仍能调整；解除故障后保存、重载、恢复自适应、Escape 关闭和再次使用。尺寸异常复验未要求修改原尺寸组件。

原逐任务目录有 14 行没有独立失败恢复证据；本版保留原记录，分别补足设置 5 行、任务视图 1 行、配对/取消/单手实机控件 3 行、编组与工作区 5 行。标定取消→失败→完成、采集与映射的完整页面链、官方参数导出、实机节目单协议和数字选择器取消也有独立补证，不拿其他任务或同一后台函数的通过代替。详情见[逐任务证据索引](TASK_ACCEPTANCE_0.2.40.md)。

## 证据使用方式

本机证据根目录为 `outputs/customer-flow-0239/` 与 `outputs/customer-flow-0240/`；`customer-flow-0240/reconciliation-final.json` 汇总每项原缺口、对应补证、源及夹具摘要。旧目录中的记录按各次实际源码摘要使用，不因目录名称或新文档而变成本版全量重跑。失败、夹具错误和源码运行中变化的未接受记录保留。

本轮 5 条编组任务在稳定页面源码上重新运行：建立工作区/成员、同步预览、发现并连接后操作、移动成员、移除成员/工作区，各自经历失败、明确恢复、终点和再次使用。真实 `WorkspaceGroups`、`GroupCoordinator` 与页面参与，外部连接和动作回执为合成输入。两项尺寸任务及设备发现/会话/历史完整链另有独立 Codex 复跑。各专项与全量可能重叠，不能相加成为“功能总通过数”。

本次完整冻结 Python 回归实际执行 1718 项：1716 通过、2 项原条件跳过、0 失败/错误，测试用时 67.679 秒，运行器 68.625 秒，运行期间 Python 源未变化。两项跳过是 Linux 专用 flock 与未提供的历史实物记录条件。证据为 `customer-flow-0240/full-final-02.json`/`.log`；同一运行器首次因隔离环境拒绝本地 socket 而失败的 `full-final-01` 原样保留，不记作通过。专项可能与该全量重叠，不累计测试总数。

最终 EXE、安装器、源文件、策略文件、原生画面捕获、覆盖安装后的配置保留和真实元数据读取，以 `customer-flow-0240/` 最终交付清单中同一冻结摘要的记录为准。本页记录源级任务证据，本页存在不代替包或安装验收；诊断目录手动补文件也不代替正式构建已携带该文件。

## 未由软件检查替代的验收

本轮未执行真实固件刷写、实际 SDK 环境切换、佩戴六动作采集、实物跟随、电机停用或多设备物理同步。标定模型质量、实际映射效果、碰撞避免、延迟与断线停用仍须接设备确认。发现与会话的合成断连输入不是实际拔线测试。

任务浮动与双区仍是同一软件内的分区，未将其写成独立原生任务窗口；现有多手无暂停/继续入口。浏览器/系统下载取消、系统文件选择器与用户私有模型不由合成接口测试冒称通过。公开二进制 Release 和真实下载安装更新另以实际发布记录为准。0.2.39 的原证据保留在[历史验证记录](VALIDATION_0.2.39.md)。
