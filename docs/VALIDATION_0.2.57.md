# 0.2.57 标定、模型和遥操作接续复查

本轮从本机保存的实际失败记录、官方 SDK 类型声明和应用入口追踪问题。隔离验证不会连接设备、重做标定、回答真实刷写确认或启动实物动作。

## 标定结果与保存身份

官方 SDK 的标定结果包含 `SdkUserInfo` 用户对象，原适配器却将其与用户名字符串直接比较。修正后，在选中官方用户后只读核对 SDK 注册表中的准确用户 ID，并在父进程、私有会话标记、采集子进程、官方事件和最终结果之间保持一致。显示名称相同不能替代用户 ID；错用户、错侧、错设备或缺失模型位置分别拒绝。

结果校验之前先保留有界原始输出，因此被拒绝的结果也有可核对的原文。确认进程退出后核对实际模型文件并保存当时的摘要，资料无法读取时不会先显示完成。损坏封包、超长记录和未知退出仍不获得成功或释放占用的资格。进程已退出而占用释放失败时，保留准确清理凭据，记录错误并允许明确重试结束。已有失败历史不会被改成成功，已有配置、用户与标定模型不会为修复而重建。

## 简化入口与会话转接

选中“标定”直接显示现有表单，没有单独的“切换到标定”步骤。选择标签或设备不会开始连接；最终“开始标定”才提交一次操作。未接入时，服务端重新发现准确设备并在官方采集子进程核对实际左右手；已有同一设备的官方 Viewer 则沿用准确占用的释放证明。

从同一手套的 SDK 会话开始标定，复用既有转接服务，先核对用户与组件，再停止准确会话、等待停用和清理确认，最后才开始新任务。其它设备、未知归属、工作区离线和未确认退出不能被自动清除。取消和失败可显式重试，不自动恢复旧连接或重复采集。

开始意图在读取状态之前登记，读取、发现和转接期间收到取消不会被后续步骤清除。界面在开始请求尚未返回时提供“取消开始”；取消请求不会错误释放原请求的忙碌状态，也不会被迟到的开始回复改回运行。

界面按请求代次和设备上下文处理结果。操作之前的空闲回复不能覆盖正在标定的新状态，也不能停止后续轮询；切换设备、离线、取消、失败重试与旧结果显示分别复查。

## 遥操作使用本次模型

成功采集的证明包含准确用户 ID、设备、侧别、模型摘要和组件身份。官方导出前后重新核对用户，导入资料包和 SDK 就绪消息必须保持同一所有者；用户绑定只在此证明匹配后更新。任何非空自定义 URDF 路径都需要核对实际文件与模型摘要，SDK 目录中保存的旧模型不再豁免。

完整接续验证覆盖保存、官方导出和导入、预览、停止与重试，进程、SDK、网络和设备使用隔离替身。模型变化、同名不同用户、错误就绪回包、未确认停用和失败清理必须保留原资料并拒绝继续。

## 固件终端显示

应用的普通表单样式曾覆盖 xterm 的隐藏键盘输入区域，增加内边距、最小高度和不同字体。本轮仅在终端作用域恢复其网格布局；官方字节仍交给原 xterm 显示。

只读导出的已完成升级历史还包含光标位置、设备属性查询和焦点追踪，原固件输入白名单却拒绝 xterm 对应回复。现在只补充准确的属性及焦点回复、界面尺寸范围内的完整光标回复，仍核对原运行、占用和设备；其它控制字符、拼接和越界回复继续拒绝。使用原始输出隔离回放，并以完整应用样式验证确认提示、一次 `y`、一次回车、ANSI 分块、换行、窗口缩放和错误文本保留；没有重新发送真实刷写确认。旧终端输出会保留当时的定位指令，回放不会改写历史，也不能恢复当时未记录的窗口缩放时序。

## 交付与边界

前端使用完整源页面和现有终端组件验证，后端使用实际服务与受控传输验证，并由非作者从不同入口和操作顺序复查。全量测试、编译代码与安装载荷比对、本机部署、配置和标定资料保留、源码同步结果分别记录于外部交付清单；测试数量不代替上述流程证据。

本轮没有再次下载或刷写固件，也没有执行真实标定和实物遥操作。软件流程的通过不能表述为已验证硬件效果；终端显示修复不会改变官方刷写确认或将用户已完成的升级重复执行。
