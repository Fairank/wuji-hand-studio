# 官方 CLI：手套标定与设备画面

0.2.30 在「连接与校准 → 官方 CLI」中使用一个设备选择和一个显示区。「查看画面」显示原版 Viewer；「开始标定」进入原版交互终端。默认 Windows 路径不再要求你先填写工作台自建的用户、左右手或覆盖表单。

## 重新连接后怎么开始

1. 打开「连接与校准 → 官方 CLI」，点击「查找设备」，在上方选择本次使用的实际手套编号。设备只需选择一次。发现记录过期时重新查找，选择本身不连接、不开始采集。
2. 如果 Viewer、手套预览、遥操作或其他工作区还在使用设备，先在所属会话中明确停止或断开。工作台不会为了开始标定而悄悄关闭已有会话。
3. 佩戴好手套后，明确点击「开始标定」。同一显示区直接打开完整官方 Human TTY。启动时仍核对所选编号、手套类型、实际左右手和会话归属；不根据编号猜侧别，也不改连另一只先出现的设备。
4. 在原版终端内创建或切换到你要使用的用户。已有这一侧的模型时，官方流程会询问是否覆盖，默认选择 **No**。在终端里用方向键、回车或文字输入完成相应提示；工作台不替你选择用户或确认覆盖。
5. 跟随官方彩色姿势图示，完成提示的动作与保持步骤。图示需要至少81列、38行；工作台保留原版尺寸要求，不重画或拉伸姿势。窗口过小时先放大显示区；原版提示若要求重启本次标定，需由你明确重新开始。
6. 在官方结果页核对实际用户、左右手和保存的 URDF；原版的 `User show` 可查看档案。**工作台显示的退出码0或 `session_ended` 只表示终端会话结束，不证明新模型已保存或质量合格。** 已有模型仍存在，也不能单独证明本次重新标定成功。

原版 Human TTY 会处理命名用户要求。若连接后绑定到 Default，官方仍会在采集前以退出码5保护退出；工作台不会提前用另一套建用户表单挡住入口。绑定用户以本次官方终端实际显示为准。

需要结束时，点击「结束并核对会话」。软件先请求原版取消并等待释放；上次宿主异常退出时，需核对精确旧会话的清理结果，未确认前继续禁止新任务。失败或取消后不自动重试。关闭显示画面、退出终端和确认硬件停用分别处理。

## 原版画面和标定指导分别做什么

Rerun Viewer 用于查看设备骨架、关节或触觉数据，不能在它的欢迎页或数据画面中完成手型标定。没有设备时，点击「无设备查看器」可以检查原版 Viewer 能否打开；它不会生成手套数据，也不进行标定。

手型标定使用同一区域内的原版 CLI Human TTY。固定官方 CLI **2026.10.12** 提供用户流程、覆盖确认、六步彩色动作指导和结果页；pywinpty 3.1.0、xterm.js 5.5.0与 fit 0.10.0 只承载终端。工作台不另画姿势卡，不按计时制造进度，也不解析原版文字猜测模型归属或成功结果。这是原版终端菜单与动作图示，不是 Studio 图形界面；直接按提示操作即可，无需编写源码。

0.2.29 已合并顶层入口，但仍在进入原版终端前保留工作台准备表单，没有达到整套复用的要求。0.2.30 去掉默认 Windows 路径的这一层重复流程。显式旧 Linux/custom 控制端的 JSONL 兼容路径仍需提前核对命名用户、左右手、已有模型及覆盖同意，不能把 Human TTY 的交互方式套到无人确认的机器模式。

## 标定保存到哪里

默认 Windows 路径的发现、Viewer与手型标定使用同一固定原生 CLI和 Windows SDK 用户库。官方产物按实际绑定的 SDK 用户及左右手保存，用户资料与程序版本分开。当前工作台不会从终端输出伪造一个“已确认用户”。

已有 Linux 用户不会静默迁移到 Windows。现有 WSL 手套预览、映射和遥操作仍使用其自身 SDK 用户库；在 Windows 完成标定，不代表 WSL 控制端已经得到该模型。两边用户名相同也不能作为同步证明。显式旧 Linux/custom 控制端按其真实环境核对；迁移应使用官方用户导出/导入流程。

本次采集、模型保存和后续映射效果需分别确认。取消、失败、未知终止或尚未核对的保存结果，都不能显示成新模型成功。本轮修复没有替你运行真实手型采集。

## 以后怎样更新

原生 CLI 发布 ZIP 离线随工作台安装包提供，默认 Windows CLI 随软件更新。设置中的「关于 → 软件更新」先检查发布版本，由你选择下载安装包；准备完成且所有相关会话结束后，再点「重启并安装」。更新保留原安装身份与用户资料，不自动迁移 SDK 用户库或升级设备固件。

显示“尚无已发布安装包”时，需要维护者实际发布新版安装包。软件更新框架已在0.2.29完成本地候选包的同软件覆盖验证；这不能代替未来公开发布后的真实网络下载验收。0.2.30的构建与覆盖安装结果另记于外部交付清单。

## 软件检查与设备验收

本版完整 Python 回归1085项，1083项通过、2项按条件跳过，用时49.954秒；标定专项90项通过且与全量重叠。独立界面验收23个唯一场景全部通过，使用隔离HTTP接口、真实终端渲染组件与合成ANSI输出；实际Viewer与设备数据另验。最终交付范围见 [0.2.30软件验证记录](VALIDATION_0.2.30.md)。

软件测试使用隔离接口和合成状态；终端渲染使用真实现成组件与明确标识的合成输出。原有 PTY 生命周期证据使用合成子进程。本轮没有运行真实 SDK手套采集或 hand-model 标定，完整动作采集、模型保存、精度、映射和断线恢复仍需重新连接设备后单独验收。
