# 0.2.39 完整使用流程与更新修复

本轮针对用户实际截图复核了连接、更新提示、固件检查和 SDK 状态之间的关系，并按完整任务验收。完整软件流程使用隔离数据和合成设备；实际安装、公开组件元数据与实物操作分别记录，不能互相代替。

## 修正依据

运行中软件已有一次官方固定 CLI 2026.10.12 的成功只读设备检查，返回准确单台设备的 `devices` / `current_version` / `latest_version` JSON。旧代码未识别这一格式，之后启动升级又被过期发现记录拒绝。本版严格识别这份已实际核对的格式，同时保留官方文本表格支持；重复字段、混合设备、未知字段、型号或状态矛盾均不作为提示或升级依据。目录和固件修订、下载及刷写仍由官方流程处理。

SDK 截图中的“先结束官方 CLI 会话”来自把纯软件版本检查也占用为独占任务。同版本状态因门禁失败被误报为错误。本版读取选定解释器与官方稳定目录可以与设备预览并行；真正更换 SDK、恢复不确定更新仍执行原跨工作区空闲与准确归属核验。

逐任务复验另发现并修正两类跨步骤问题：节目单已完成后，迟到的保活错误会覆盖正常结束；现以独立公开运行标识、准确租约与本地请求世代消歧，保留真实失败及新任务错误。软件安装助手失败后，旧结果会不断覆盖下一次检查；现确认原助手退出后才解除本次结果关联，保留历史，存活或退出未知的助手不能被第二次安装替换。固件异常恢复也改用已实际核对的准确设备检查格式，不猜测未经证实的版本读取包装。

## 完整路径

设备目录主操作明确为连接，标定和遥操作留在原任务中；“设备更新”收进所选设备的“更多”。连接不打开升级窗口。明确连接前在已有原版组件中执行有时间上限的准确 SN 只读版本检查；超时只在确认该只读进程和占用都已结束后让出，不取消手动任务或升级终端。后台检查不能抢占正在使用的设备。

可用更新以不抢焦点的提醒与菜单角标显示，支持“稍后”；相同版本在当前软件会话中不重复打扰。已连接 Viewer 的准确 SN 从同次启动报告和原设备元数据合并，不凭序列号猜型号。读取提醒只采纳已有检查结果，不发起新的设备查询。

更新时由用户明确选择“结束预览并检查更新”，只结束同 SN、同会话标识且已核实为自己拥有的原版只读 Viewer。其他工作区或清理未确认时不继续。旧发现过期时，明确版本检查自动刷新一次发现，再核对原 SN；不会换查另一台设备。官方确认方案有独立短有效期，不再误用发现的 30 秒有效期。

打开官方升级仍需原版终端中的最终确认，没有自动 Yes、强刷或全部设备入口。官方进程退出仅表示流程结束，之后明确读回设备版本才能确认结果。重新检查不显示上一次已结束的终端。只读检查与真正升级的失败及未知退出分别恢复，不能用检查进程退出冒充固件升级成功。

## 全软件界面

复核设备、单手/多手展示、遥操作、官方查看/标定和设置页面。正常状态减少重复说明、不可操作的占位按钮和已完成安装项；技术资料收进原详情，身份不符、未知停止、进行中和可操作错误保持可见。中英文、简单/完整模式和窄窗口均检查布局及交互。复用现有官方画面、标定指导、终端和任务框架，没有新加客户模式。
