# 0.2.75 标定、重连与再次进入验证

本轮针对“标定结束后断开、重新接入并再次进入标定页”的顺序，沿用原有统一用途转接入口，不更改界面设计、人员资料、标定方式选择或 SDK 连接协议。

- 已完成接续的 SDK 会话短暂缺帧时，保留画面未就绪状态，但不再将缺帧反推为接续任务仍忙。真正工作线程、未确认清理、配对实机及切换归属的限制继续有效；不后台重连。
- 完成结果只属于原标定操作；观察到同设备的明确后继 Viewer 会话后，旧记录留在原有历史区，后继会话退出或短暂未知不会使它重新占据当前工作区。真正运行与清理未完的标定仍留在当前区域。
- 通过实际服务类和隔离的官方 CLI、SDK、进程、文件替身，检查完成、继续使用、短暂缺帧、明确转回 CLI、同人覆盖、新增人员、取消、失败及明确重试。原版终端结束后，明确遥操作可沿用该人员保存的模型，不要求再标定；不将终端正常退出冒称结构化标定成功。
- 页面检查使用完整现有 HTML 与真实脚本，分别覆盖引导和原版终端、人员与方式保留、旧回复、换页及重新进入；原失败与非作者异序复查另存本地证据。

现场只读检查确认原生界面样式完整；此前实物断联的首因仍未确定。软件复现的缺帧忙状态问题与现场终端会话是不同状态，不能用一个代替另一个。未执行真实设备连接、固件写入、SDK/CLI 调用或 MuJoCo 物理。原生诊断截图接口的既有超时仍保留，DOM/样式检查不代替截图。
