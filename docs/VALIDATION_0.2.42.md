# 0.2.42：CLI 与遥操作会话切换

## 修复目标

既有 CLI→遥操作入口只完成关闭 Viewer、查找手套和读取用户，尚未完成手套接入；反向缺少对应移交流程，活动设备的控件又要求先手动断开。用户因此需要重复连接。新版本沿用官方 CLI/SDK，在一次明确切换操作中校验目标、确认旧所有者释放、接入新模式，并沿用已核实的用户与标定资料。

设备目录中的候选选择和页面导航仍不自动连接；独立设备任务不受其他设备切换影响；真实跟随仍需明确开始。不能用线程停止、进程退出或界面 busy=false 代替 SDK 资源释放和目标停用确认。

## 必须独立验证的路径

- CLI→遥操作与遥操作→CLI：成功、停止失败、接入失败、再次使用。
- 同一目标重复请求与另一明确目标切换；目标或用户不全时保留原连接。
- 用户/左右手/标定内容连续性，以及既有“标定完成→遥操作”接续。
- 切换期间的旧异步回复、重复点击、取消、另一工作区所有权和未知释放结果。
- 正常桌面安装后的首页发现与设备选择；不因扫描自动接入。

## 已完成的软件验证

后端最终独立回归 337 项通过，包含目标环境或组件缺失时保留原连接、原 SDK 清理失败的明确重试、超时与迟到回复、同目标复用和跨任务隔离。另一审计独立通过 229 项 SDK 清理相关回归，并用实际 Handler、Controller、切换协调器及原读取线程完成 6 组集成检查；外部设备和进程输入由测试替身提供，没有实物动作。

全量最终源码回归运行 1,795 项：1,793 项通过，2 项按既有条件跳过，失败和错误均为 0，运行期间 Python 源码未变化（`full-final-06.json`）。

页面已通过 17 条完整流程：正常和窄窗口、双向切换、实际用户身份、失败恢复、重复点击、丢失响应后的同请求查询、任务嵌入与旧状态隔离。最终后端增加目标能力预检后，另外通过 2 条真实页面到协调器的补查：缺少组件或运行环境时不停止原连接，修复测试环境后明确重试才接入。4 个网页文件与前 17 条验收完全一致；17 条记录不冒称在最终后端全部重跑。具体结果、源码哈希和失败尝试均保存在外部 `outputs/customer-flow-0242`，不覆盖旧记录。

本版自动交接支持 Windows 原生官方 Viewer 与已配置的遥操作控制端。非原生官方 Viewer 的旧接口不能证明同等的精确会话释放，自动交接在预检拒绝，原连接和既有入口保留。
