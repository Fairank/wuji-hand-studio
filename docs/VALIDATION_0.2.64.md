# 0.2.64 统一设备用途与标定转交

本轮检查设备目录、CLI 画面、标定接续和遥操作的实际调用链。用户只需选择目标设备，明确选择另一种用途时，后台确认原进程退出后接入同一设备；不同官方进程的连接资源仍分别核对，不把页面选择或历史记录显示成实际在线。重新载入、返回、内部虚实模式切换及每五秒只读发现均不产生新的连接。

## 已复现的问题与修改

- 设备目录的预览按钮原本只跳页面，旧接续入口只扫描但未打开准确手套。相同用途操作改用现有 `ConnectionSwitch`，显示实际当前设备与用途，隐藏普通页面内重复的查找、选择及接入；高级连接设置仍可访问。
- 旧工作台左右手默认值可能与运行中的 CLI 手套不同；当前连接的实际左右手现在优先用于转接，用户明确选择不符的型号仍拒绝。已接收的 SDK 会话优先复用，不因旧的标定接续提示再次退出或导入。
- 普通 CLI 预览转遥操作时，Windows 已存官方佩戴者资料未转交给 SDK。新增私有档案转交，使用官方 `user show`、用户注册 UUID 和未修改的官方导出 ZIP；唯一定位实际模型并核对字节，SDK 预览、导入和加载读回后才打开准确手套。不制造一次“标定成功”记录，不放宽原有新标定证明。
- 前后端控制环境的广播范围可能不同。沿用现有地址传递流程，只携带官方刚观察到的准确目标地址，SDK 连接后再核对真实序列号；错误身份不订阅、不启动跟随。
- 后端慢速核对发生在发布等待任务之前，页面无法准确取消。现在先发布本次请求、任务编号和截止时间，核对后再次检查取消，未释放原连接前失败不会接入新设备。
- SDK 模型就绪回调因原标定内容变化而拒绝后，原读取循环直接退出，丢失真实退出回执，后续重试永久受阻。现在发送准确本次退出并继续读取确认；后续数据不能把拒绝改成成功，缺少、错误或失败的清理回执仍保留阻止状态。
- 官方资料已导入但本地保存确认失败后，新一次明确请求的转交编号和 ZIP 打包时间不同，原实现无法接续已验证的待保存记录。沿用原恢复流程，额外核对同一佩戴者、工作区、手套、左右手、模型及完整 SDK 组件，再提交原记录，不重复导入。内容、身份、已有记录或实际 SDK 资料不同仍拒绝；原新标定运行证明不放宽。
- 已存标定首接与往返复用都显示已应用的准确佩戴者和左右手；不要求本轮重复导入才显示成功。原设置的超时值传给实际 SDK 工作线程，未设置时使用原默认值。
- 页面待请求归属准确服务与请求；离线后旧成功、失败及收尾不能覆盖或解锁新的用途切换。相同用途完成结果过滤服务器私有转交信息。

## 本轮流程证据

使用实际 Controller、HTTP Handler、ConnectionSwitch、官方画面生命周期、GloveBridge 读取循环和 SDK 控制工作线程；官方网络、进程和设备端点采用严格替身。完整执行 CLI 右手但工作台旧默认左手 → 现存标定转交 SDK → 新鲜 SDK 映射预览 → 同用途重复选择不重开 → SDK 清理并恢复原人员 → CLI → 相同标定 SDK。关闭拒绝后保留准确原归属，再由明确重试完成转接。全程没有启用电机或开始跟随。

异常流程包含原始模型同尺寸改变、UUID/左右手/工作区/控制配置改变、迟到模型回调、取消与超时、错误或缺少退出回执、关闭失败后明确重试，以及无标定的 Default 用户在释放原 CLI 前拒绝。多个官方档案和左右手分别转交并读回，原始导出及其他用户资料保持。非作者另外检查原生文件门与读取线程的锁顺序，在慢速导出期间更换任务、配置、型号或 SDK 上下文，均不得提交旧映射。

完整源页面使用隔离回环 HTTP 与代码 Playwright 检查全局用途入口、当前设备显示、服务变化和取消。Browser 插件不可用，使用已安装的无头 Edge；没有桌面鼠标键盘操作、浏览器原生下载或 IDM。

最终回归、页面与源码一致性、编译模块、本地安装包内容、本机安装后运行文件及用户资料保留、Git 同步由本轮外部交付清单分别记录。原失败、测试夹具修正和后续复查分开保存，不因用例数量代替具体操作链。

## 边界

没有连接真实设备，没有进行固件刷写、真实标定采集或实物运动。合成完整控制链不证明真实 USB/网络时序、温度、长期稳定性或运动质量。保留显式实机跟随确认；仅选择遥操作或切换虚实模式不会启动实物动作。本轮按既有授权直接更新本机和同步现有源码分支，不发布或上传安装包。
